# r13 → 当前开发版存档升级调查（2026-10-19）

这是本次调查的证据快照，当前规则、缺陷与实施状态以[公共底座](../state/infrastructure.md#r13存档直升范围)为准。

## 范围与结论

- 起点：正式 `v1.4-r13`，解引用提交 `03964e418fe79112a8c9e57408391d598a322538`，不是猜测的某个开发版本。
- 终点：`d5a8d84` 上当前未提交工作树。当前 live 尚未加入本调查提出的任何迁移。
- 比较 r13 的 141 个顶层 C# 文件与当前 191 个文件，定位保存入口、子序列化、注册类型、枚举、行为注册和世界对象引用。
- 当前不能承诺 r13 直接升级。已找到可复现的数据丢失与加载异常；源码没有显示必须彻底放弃旧世界的结构障碍，具备实施定向升级的条件。
- 用户没有未经新版覆盖的 r13 存档，本次没有解析完整 `.sav`，没有启动游戏。不能把这次核查当作完整旧战役升级验收。

## 已确认的衔接问题

| 项目 | r13 → 当前的变化与后果 | 必要处理 |
|---|---|---|
| 地图通知类型 | `GwpSaveableTypeDefiner` 删除 localId 2 的 `PlayerBountyBehavior.BountyMapNotification`，类型本身也被删除。r13 会把此通知放入原版持久通知列表；仍有通知对象的存档失去类型定义 | 保留原类型全名、ID 和可读结构，让旧通知正常失效；不重新开放旧接案弹窗。需在保存系统解码阶段验证，读档后的清理无法替代类型注册 |
| 请愿差事 | 新增 `GWPP_IssueDutyPausedAtHours`，读取条数取所有列表的最小长度；旧档缺新列表，结果为零，旧承办记录被清空 | r13 记录默认未暂停，保留人物、事项、结束时刻；不能把缺列表解释为没有任务 |
| 重建差事 | 新增 `GWPP_RebuildPausedAtHours`，同样使所有旧任务（包括排队任务）被跳过 | 补齐未暂停语义，保持排队、承办人、已开工与截止时间 |
| 收养善后 | 旧 `ActiveEndHours` / `ActiveAwaitingResupplyFlags` 换成 `ActiveRemainingHours` / `ActiveLastWorkHours`，缺新列表使旧在办记录丢失 | 按旧是否开工、截止时刻换算剩余驻留时间，未开工保留完整工期；旧等补给状态转入当前行程/驻留判据，不能把赶路算工时。已收养人物、来源、冷却保留，不能再领一次孩子 |
| 协力队伍 | 新增 `gwp_enf_assist_release_reasons`，旧档读出 null 后仍按 `releaseReasons[index]` 取值；只要旧协力组非空即空引用 | 缺值表示没有待释放原因；保留协力组、成员、原版军团及分散状态 |
| 旧练兵交接 | r13 保存七组练兵交接/升级时刻数据；当前训练行为 `SyncData` 为空，新机制改为老兵送村 | 显式退休旧会合任务并释放旧行程占用，保留两支实体队实际持兵和经验；不能凭旧任务再凭空发一批运兵兵员 |
| 新宗教系统 | r13 没有 `GwpFireswornBehavior`。读档不会自动重放新档事件，家乡信众与初始守村兵配置没有执行 | 定义一次性的旧世界启用步骤，并保存完成标记；后续存读不得重复造人、造兵或重复配置 |

### 宗教系统的准确边界

原版 `CampaignBehaviorDataStore.LoadBehaviorData` 找不到行为记录时不调用其 `SyncData`（另有按类名匹配旧标识的路径）。因此，真正的 r13 档不是对新增宗教行为传一份全缺键数据。

当前宗教每日 `RestoreHomePriest` 会调用 `InstallPriest` → `EnsureVillage`，能够建立家乡村记录和祭司；但不会执行新档 `OnVillageRebuilt` 的信众配置及初始守村兵。`GrowSworn` 之后可按领主驻留、户数等正常机制增长。因此不能称作“宗教永远无法启动”，也不能称作“自动得到与新档相同的起点”。

此前本机崩溃则是另一条路径：旧开发存档已经有宗教行为，缺后来新增的 `GWPP_FsDedicatedMarketTrips`，直接索引空列表。该缺键也需要在对应格式中处理，但修它不能代表 r13 全路径兼容。

| 玩家送信队 | r13 已写出当前要求的完整 15 段，目的/阶段枚举数值一致；不能因当前删除了更老格式的宽松读取就断言 r13 不兼容。实体队、货物与借船台账仍需联合验证 |
| 玩家承办结果 | r13 已将六段结果写入 `gwp_case_outcome_state`；当前同格式。删除的更老分散结果读取不是正常 r13 写入格式所必需 |
| 案件、履历、职业 | 主要案件/任务键及犯罪类别、流程、职业枚举值保留。r13 已另存履历，删除旧案件行里的冗余履历字段不等于删除正常 r13 履历 |
| 回执与追账 | r13 已有逐笔回执、追账、俘虏等保存字段。删除的旧聚合计数不能用于重复导入款项；前 r13 残留状态不能仅凭 r13 写入方法证明已归一化 |
| 旧追截队 | 新增 `gwp_enf_dp_envoys` 读取有缺值/下标判断，旧队按非使者恢复；不能把所有旧临时队当作待清理使者 |
| 新案件使者与冷却 | r13 没有的新列表走缺值空集合路径，未见与协力释放原因相同的直接 null 索引；已宣战旧案仍需核对接续，不重放已完成谈判 |
| 世界资源 ID | 检查 items、spnpccharacters、spspecialcharacters、spclans、gw_equipment_sets 五组 XML，旧对象 ID 未发现删除，新增执勤旗与火誓新兵。这不证明旧实体会自动刷新所有新模板属性 |
| 玩家执勤旗 | 原入会标记仍保存。当前已有灰袍领主对话补领入口，旧会员无旗可以领取；不需要重复执行入会奖励 |

删除的旧纯化预算、强制驻城出击登记与训练交接不能统一当作“垃圾键”直接忽略：虽然新机制不使用旧登记，仍需在实施时核对原版实体移动目标、军团及持续任务是否残留。新增婚后身份名单和只在新档设置的满关系也需区分：保留旧世界关系不等于重放新档关系奖励。

## 直接执行的证据

命令：`python tools/Audit-R13SaveUpgrade.py`。

工具从正式 tag 提取四个生产保存方法，生成各有一条任务的 r13 数据；用当前生产读取方法读取同一份数据。存储接口的缺键语义直接使用本机反编译的原版 `BehaviorSaveData.SyncData<T>`。任务实体受控，收养地图通知清理及案件池容量副作用用桩隔离。

```text
BASE=03964e418fe79112a8c9e57408391d598a322538
Issue: r13=1 current=0
Rebuild: r13=1 current=0
Adopt: r13=1 current=0
Assist: r13=1 current=NullReferenceException
CONTROLS=8 PASS; engine entities stubbed; no .sav loaded
```

八组对照为四组 r13 自读和四组当前版本自读，均保留一条任务。前四行是发现的兼容缺陷，不是修复已通过；脚本退出 0 表示调查执行成功，不表示升级兼容。

## 实施顺序与验收范围

1. 先恢复旧类型可读性，再处理旧字段转换；不靠清空任务绕过崩溃。
2. 接续请愿、重建、收养、协力、玩家委托/送信/练兵订单、借船与实际财物；对已删除旧机制做明确退休处理。
3. 在旧世界中启用新宗教体系；完成标记进入存档，再读档不能重复执行。保留死者、既有关系、已花费用及实际库存。
4. 用正式 r13 写入结构构造有/无任务、旅行/驻留/战斗、已交差/待交差的组合；升级后再保存读取，核对人物、兵员、货物、金币、俘虏、时间及队伍归属守恒。
5. 实际 `.sav` 的保存系统类型解码、原版世界实体引用与加载事件顺序尚无证据。不能用本工具的受控执行替代该层验收。

这次只调查并更新项目规则、缺陷记录和复现工具，没有修改业务 C#、构建或部署兼容版。

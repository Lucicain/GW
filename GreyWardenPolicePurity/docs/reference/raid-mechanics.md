# 原版烧村机制与信众村守备

原版证据来自原版源码库 `../BannerlordSource/v1.4.8/managed/TaleWorlds.CampaignSystem/`（`tools/Build-VanillaSource.py` 生成），
监控证据来自 2026-10-14 一局（`GreyWarden-AI-Diagnostics.log`、`GreyWarden-Case-Events.log` 及 10-12 归档）。
这是参考资料，不是规则；模组现行行为以 `docs/state/` 为准。

## 1. AI 选不选这个村去烧

`DefaultTargetScoreCalculatingModel.GetTargetScoreForFaction(..., Army.ArmyTypes.Raider, ...)`，
由 `AiMilitaryBehavior` 在攻城 / 烧村 / 防守 / 巡逻候选里比分取最高。烧村分是下面各项相乘：（依据：C#反编译）

| 项 | 取值 | 在哪一边 |
|---|---|---|
| 兵力比 `num` | 进攻方战力 ÷（村里民兵 + 驻军 + 村里 `Aggressiveness>0.01` 的部队战力 + 王国份额项 + 0.1），封顶 2。**进攻方战力 < 0.75 × 分母时直接返回 0，不烧**（即村里守军 ≥ 进攻方约 1.33 倍） | 村子这边 |
| 村子价值 `num23` | `(SettlementValueForEnemyHero / 50000)^0.5 × 1.5`；价值来自 `Settlement.GetValue()`（户数/繁荣）、同文化 ×1.1、自家村 ×1.1、地理优势；所属城镇存粮 <100 再加最多 30% | 村子这边 |
| 缺钱 `num24` | 进攻方家族金币 <10000 时最多 +0.5（单队）/+0.25（军团） | 进攻领主 |
| 村子已受损 `num25` | `0.875 × (2 − SettlementHitPoints)`：烧过一半的村更招人 | 村子这边 |
| **关系 `num27`** | 进攻方家族与**村主家族**关系 >0：`1 − 0.8 × √关系 / 10`（关系 100 → ×0.2，25 → ×0.6）；关系 <0 最多 ×1.05 | 两个原版家族之间 |
| 玩家国王指令 `num28` | 玩家是王时按外交优先级 ×0.65 / ×1.3 | 玩家 |
| 已在烧 `num29` | 当前目标 ×1.3，正在烧 ×1.5 | 进攻领主 |
| 距离 `num21` | 越近越高，烧村上限 ×3 | 两边 |
| 进攻姿态 | `PartyObjective.Aggressive` ×1.2 | 进攻领主 |

- 原版这里**没有**仁慈等性格项。社区说的「关系影响烧村」就是 `num27`，而且是和**村主家族**的关系，不是和村民或灰袍。
- 村外部队只在**村子已在被打**时计入（`num17`），且要求 `MapFaction == 村子的 MapFaction`。灰袍家族不入王国，
  火誓者巡逻/紧急队与原版村主不是同一 `MapFaction`，所以**在外的巡逻对 AI 选不选这个村没有任何影响**。
- 模组现有 `PoliceRaidDeterrenceModel` 在此分数上乘 `0.65^震慑点数`。倍率只取决于进攻领主，不取决于目标村，
  所以它只把被震慑的领主从「烧村」推向攻城/防守/巡逻；他仍要烧时，挑哪个村的排序不变。

## 2. 烧村怎么进行

`RaidEventComponent`：（依据：C#反编译）

- 建立烧村事件时，村子的原版民兵队（`MilitiaPartyComponent`）加入守方，先打一场；守方还有人时不开始烧。
- 守方人数为 0 后每小时扣村子耐久 `(√进攻人数 + 5) / 900`（100 人约 60 小时烧完）；每扣一笔，户数减
  `扣的耐久 × 0.5 × 当前户数`，按每户 4 金币给进攻领主。
- 耐久归零 → 村子变成「已烧毁」；守方打赢 → 恢复正常。民兵抵抗打完后 AI 会重新排队继续烧。
- 原版 `CharacterRelationCampaignBehavior.OnRaidCompleted`：烧完按损伤扣进攻方与村里要人的关系。

## 3. 本局监控：信教后守备为什么掉

2026-10-14 一局 `DAILY_VILLAGE` 末日快照：（依据：实机诊断）

- 未信教村的原版民兵贴近原版平衡点 20 + 户数/10（406 户 57 人、629 户 80 人）。守村队上限为信众户 ÷ 2（`HouseholdsPerGuard`），只按信众户算。
- 祭司最强的村，原版民兵停长并被烧到 0～5；守村队总人数（`population`，含在外）只到上限（户数/2）的 25%～75%，
  在村的又只有总数的约一半到六成（例：EN5_1 总 99、在村 57；S8_1 总 112、在村 59；A6_2 总 76、在村 42）。
- 结果：300 户上下的信众村在村守备 20～60 人，同户数未信教村是 40～60 名原版民兵；EN7_1、ES1_2 在村 0 人。
  守村兵多为 2 阶狂信者，武装率普遍 0～10%；AI 估战力只看兵种，不看装备。
- 本局约 10 天烧村记录：同一领主反复烧同一片（lord_1_41 连烧 EN2_1/EN2_2 五次，累计平民伤亡 599 后才在
  第 13 天左右被灰袍抓获结案）。被抓后首次震慑只把他的烧村分 ×0.65。

## 4. 社区做法（只记杠杆，不改第三方）

- Party AI Overhaul and Commands（Nexus 493）：按进攻方与玩家的关系、文化，降低对朋友领地的烧村/进攻意愿——即放大 `num27` 一类。（依据：网页 2026-10-14）
- Nexus 389（烧村类模组）：烧村时真实调出附近城镇驻军，加上村民抵抗。（依据：网页 2026-10-14）
- Village Management（Nexus 8109）：用村里民兵组巡逻队清周边。未见说明是否参与防烧村。（依据：网页 2026-10-14）

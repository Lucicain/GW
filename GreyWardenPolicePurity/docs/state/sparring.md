# 与灰袍领主切磋（城中竞技场与野外）

> 当前状态：现行规则（2026-10-05 从源码提取）
> 最后验收：未建立检查点
> 已复核至：`1f84971`（2026-10-15）
> 覆盖源码：`GreyWardenSparringBehavior.cs` `GreyWardenFieldSparringMissionController.cs` `GreyWardenSafeTroopSupplier.cs`
> 待实测：无

玩家与灰袍领主的友谊赛。野外执法里罪犯要求单挑时，也借用这条管线（见 [`field-arrest.md`](field-arrest.md)）。

## 谁能约

- 对方是灰袍领主（`GwpCommon.IsGreyWardenLord`），活着、没被俘、没受伤；玩家也没受伤、不在战斗中，双方阵营不在交战。
- 正在进行的是执法对话时，不出现切磋选项。
- 在城镇里：只有这座城有竞技场才能约，用原版竞技场单挑。
- 在野外：对方必须有自己在场的部队。
- 切磋没有奖励，也不影响关系或声望；只有执法单挑会把胜负交回执法流程结算。

## 城镇：原版竞技场

- 先关掉对话任务，回到地图状态后直接打开竞技场单挑场景。
  在对话里直接进竞技场地点，会变成原版竞技场主持人的闲逛场景。
- 赛后有欢呼音效，胜负各有一句台词。

## 野外：借用本地战场场景，不建 MapEvent

- 地图上的对话属于一次 PlayerEncounter。开新任务之前先和平地关掉遭遇，否则关掉对话后，遭遇菜单会把它当成真的进攻。
- 在城堡里谈的：先真正离开据点，下一帧再开场景。否则赛后引擎会恢复过期的 `castle_outside` 菜单，原版菜单状态可能出错。
  这也对应「双方走出城墙去比试」的情节。（依据：实机诊断 2026-07-25）
- 真正的战役战斗永远优先。排队中的切磋不会在战斗之后或处理俘虏期间启动，也不会叠在 MapEvent 上。
  排队状态不进存档。
- 出生点沿用原版野战的选点：把战役地块和遭遇方向交给原版出生路径选择器。
  不给这些值，引擎会随机选路径和朝向，双方会站到同一侧。
  任务模式用 `TownMerchant`：有自由视角和战斗状态 UI，不需要部署、战斗序列和边界视图。
- 流程：两队列阵，间隔约 100 米 → 对方前出 → 玩家走近后对话，选骑战或步战 → 开打。
  - 骑战时玩家没有马：对方队里一名骑兵过来下马，把马借给玩家，再走回队列。
  - 步战时玩家 20 秒内不下马，判玩家输，对方会说一句「说好步战你却不下马」。
- 胜负：任何一方被击倒即分出胜负，胜利表现用原版藏身处头目决斗的那套预设。
- 野外出兵沿用原版自定义战斗的分配顺序，但换成战役里安全、不持久的 agent 来源（`GreyWardenSafeTroopSupplier`）。
  场景对话要求来源的参战方是 `PartyBase`，原版 `CustomBattleAgentOrigin` 给的是 `CustomBattleCombatant`，会转型失败。
  伤亡回调都是空操作，切磋不改动战役名册。

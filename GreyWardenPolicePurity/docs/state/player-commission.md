> 覆盖源码：`PlayerBountyBehavior.CaseSettlement.cs` `PlayerBountyBehavior.Custody.cs` `PlayerBountyBehavior.Affairs.cs` `PlayerBountyBehavior.QuestAndNotification.cs` `tools/tests/test_case_envoy_scenarios.py` `tools/tests/test_case_custody.py`
> 待实测：目标逃亡/待重建部队时事务和交差对话的无责撤回、保留原案及重现后再派；第三方领主/地牢赎买与旧档接续；委托目标被打垮但人跑掉时，震慑照上、不再计被捕次数（和灰袍自己打垮未俘一致，见 case-enforcement.md「震慑口径」）

本文件只写普通悬赏**结果怎么判**、何时可以交差、交差拿多少。接单、支援与账本见[玩家声望](player-justice.md)，谈判见[野外执法](field-arrest.md)，负声望任务见[赎罪](atonement.md)。普通悬赏的底层持案查询现由 `GwpPlayerCaseAssignment` 汇总给外部调用，原有结果判定与报酬规则保留。（依据：源码复核2026-10-15）

读档后重新核算仍在追踪的委托罚金时，以 `CaseHero` 的英雄 ID 取开放案。多名嫌犯可以同在玩家主队，按部队 ID 取第一案会把另一人的罚金写进当前委托。（依据：源码复核 2026-09-27）

读档与回执业务直接执行，移除无依据的通用吞异常包装；故障观察器不改变结果判定。规则见 [代码健康](code-health.md)。（依据：源码复核2026-10-14）

## 用户规则

玩家亲自击溃目标部队或将目标俘获，均可完成委托；目标被第三方俘虏不等同玩家完成。NPC追责规则归 [case-enforcement.md](case-enforcement.md)。（依据：用户裁定、源码复核 2026-10-19）
用户 2026-09-24 补充：打垮对方部队就算完成委托、照付办案费；能把人押来更好，
押人时灰袍另按原版赎金价向玩家收购。

目标被第三方俘虏、暂时没有部队时保留委托及未了罪责；玩家可选择赎买接管、无责撤委托或继续等待人物恢复可追踪状态；只有明确人死亡或原追责已经实际结清才按外部结案撤委托。玩家已亲自打垮目标的原完成标记照常有效。`test_case_envoy_scenarios.py` 执行真实核对与销案入口验证这些分支。（依据：用户裁定、离线执行 2026-10-17）

共享专项本轮扩展[使者无赶路时限](case-envoy.md)时，玩家第三方俘虏/暂失队及亲自击溃后的结果分支一并复测通过；玩家任务的期限、交差和报酬代码没有随使者修改。（依据：源码与离线回归2026-10-18）

## 目标不可追踪时的无责撤回

案犯被第三方俘虏后允许玩家向扣押者赎买接管；第三方扣押、逃亡、临时Disabled、没有活跃部队等待重新出现，均可无责撤回委托，原未结罪责保留。撤委托不伪造玩家击溃或抓捕结果，也不结清罪犯案件；接管实际到玩家囚笼后才进入既有押人交差链。当前45天期限未改为暂停，玩家可主动撤回。（依据：用户最终裁定2026-10-21）

没带部队、住在城镇或城堡里的目标不算失去踪迹，不开放无责撤回，委托显示其所在城并开放进城搜捕，规则见[进城搜捕](city-search.md)。（依据：用户裁定2026-10-21）

CanWithdrawUnavailableCommission是事务及灰袍交差对话的共享门槛，依现有IsTracking/HasCompletedEnforcement/开放案判断：玩家已击溃或结算的案子仍走交差，目标死亡/原案已结清仍走外部结案，不用撤单抹掉已做的事。撤单仅取消现有Quest并EndBountyTaskState释放玩家占案、护送及本次追责战争，不关闭CrimeRecord、不扣声望；原案留池，待英雄恢复后原筛选才再次派案。赎买仍额外要求真实IsPrisoner和实际扣押者，不把逃亡目标当可交易俘虏。无新增保存键，当前已有委托读档可直接用新门槛。（依据：用户最终裁定、原入口接续及源码2026-10-21）

事务暂失目标显示失踪/等待重建与撤回说明，不沿旧部队显示战力或位置。情报解析同样先检查共享失踪口径，不能拿旧部队ID继续播报已经逃亡的人；恢复带队后回写新ID。（依据：用户当前任务反馈与源码复核2026-10-21）

赎买入口面向实际扣押领主，地牢扣押时面向在场的属主族长或总督。使用原版交易报价、赎金估值与接受判定，仅交易金币、物品及本案犯人；移交调用原版TransferPrisonerAction，不要求玩家与犯人开战，不走释放赎俘条目。成交后实际进入玩家囚笼才登记抓捕；取消或报价不足不转人、不撤委托。当前委托详情及灰袍交差对话均可无责撤回尚未完成、目标不可追踪的委托。没有新增存档键、保存类型或自动暂停期限。（依据：用户选择、源码与原版托管方法执行2026-10-20）

## 判定顺序

`ReconcileCaseOnTick` 每秒一次（对话中、玩家在战斗或遭遇中时跳过）：

1. `ReconcileAssignedCase`
   - 目标在玩家队里当俘虏 → 按拘捕结案（`NotifyCaseClosedByCapture`）。
   - 仍在追捕，且目标死亡或原账目已经实际结清，并且玩家没有战场击溃标记 → 外部结案，只领辛苦费；第三方俘虏与暂时失队继续等待。
   - 目标重新拉起队伍时刷新追踪的队伍 ID。
2. 本场战斗的结算（`_caseBattleToReconcile`，由战斗结束登记）
   - 目标在玩家队里当俘虏 → 震慑计拘捕。
   - 玩家打垮了他但人跑了（`_caseTargetDefeated`）→ 震慑照上但不计拘捕；**停止追踪、
     转入交差状态、清除期限、撤回护送**；任务标为可交差，提示“你在野外击溃了…回去复命吧”。
   - 没打垮、人还活着 → 委托继续。

`_caseTargetDefeated` 在战斗结束时由 `NotifyCaseBattleOutcome`（玩家胜且目标在败方）置真。
原版战后可能解散败军；玩家的战场击溃标记交战后结算处理，不因暂时失队被误撤委托。

## 期限

期限到时：已打垮或已和平了结（`HasCompletedEnforcement`）→ 转入交差，不作废；
否则委托作废并撤回护送。

## 交差入口与报酬

与任意灰袍领主对话“我来汇报委托”，条件只有“有委托在身”（`HasBountyTask`）。派人复命同口径。

**俘虏怎么交**：不走分兵界面。活捉目标后下一次核对（`ReconcileAssignedCase`，玩家不在对话、
战斗、遭遇中时每秒一次）调 `NotifyCaseClosedByCapture`，记下押人对象与押人估价
（`_pendingPrisonerHeroId` / `_pendingPrisonerAssessed`），委托转入交差。交差界面（亲自交与派人
复命都用 `GwpAssetPayment`）只在 `CanDeliverCasePrisoner` 成立时列出这名俘虏：押人估价 > 0、
本人仍是俘虏、并且在玩家主队里。派人复命时选中俘虏，出发时由派遣流程直接把人转进送信队，
到达后转给接收的灰袍领主。

**交差入口先补登记**：每秒核对在对话中、战后遭遇界面未退出时跳过，刚打完直接去交差会赶在
登记之前。所以两个入口——对灰袍领主说"我来汇报委托"（该句的 consequence）、派人复命打开交差
界面前——先调 `RegisterCaptureInCustody`，与每秒核对用同一段登记逻辑。只在这两个时刻多查一次，
不增加每帧/每秒开销。（2026-09-26 诊断：改前两次打开时人已在主队但 `pendingHero=-`，移动后才登记。）

- **办案费** `CalculateCaseFee(cap)` = `GwpCaseSettlementRules.Reward`：底薪 + 玩家阵亡 × 抚恤
  + 罪责点 × 单价，封顶为本案应缴额 `CaseAmountDue`（指定罚金、押人估价、野外账本估价取最大）。
- **打垮未俘**：交钱复命即可领整案办案费。打垮过的案子，只有交出的钱少于**实际从他手里收到的**
  钱（`CaseReportSuggestedPayment`）才会被追问去向；没收过钱就不追问。未打垮的案子仍以应缴额为准。
- **押人**：`PrisonerCaseFee` = 押人估价封顶的办案费 + 原版
  `RansomValueCalculationModel.PrisonerRansomValue(俘虏, 玩家)`。亲自交与派人交相同。
- **被别人了结**：只付辛苦费（底薪 + 阵亡抚恤），不含罪责段。
- 所有报酬从灰袍司法公库（族长金币）支付，公库不足时只付得出多少付多少。

任务说明 `gwp_bounty_quest_reward` 写明：击溃部队、收罚金或俘虏均可复命，活捉另按赎金价收购。

# 玩家练兵订单与随行练兵队

> 当前状态：当面及使者共用混合兵种订单页，待实测
> 最后验收：`03964e4`（v1.4-r13 构建；2026-09-26 用户确认）
> 覆盖源码：`GreyWardenTroopRequestBehavior.cs` `GreyWardenTroopRequestBehavior.Cohort.cs` `GwpTroopOrderScreen.cs` `GreyWardenPolicePurity/Core/Troops/TroopOrderComposition.cs` `PolicePartyTroopUpgradeModel.cs`
> 待实测：当面和使者混合下单、精确扣除小数声望、取消和名额不足；前后阶混订保留低阶成品；旧订单与同版混合订单存读、一次交齐和练兵队归还伤兵与经验

本文件只写玩家向灰袍练兵官订兵这条线。练兵官挂名与全队兵种配比取向
（`GreyWardenTrainingBehavior`）见[日常练兵](warden-training.md)。共用升级模型新增的守村灰袍付款选择只在信众村民兵升级范围生效，不改变订单锁定、交付或分支；费用归属见[村庄](firesworn-villages.md)。玩家订单原有随行队加经验保留；临时换兵来源资格由差事表 StockExchange 口径判断。自主运兵不占用领主、不取消订单，规则见[运兵](warden-training.md)。（依据：源码复核 2026-10-09；用户裁定、源码复核 2026-10-15）

兵员搬运及建队编号规则只在 [临时队](temporary-parties.md) 定义，选兵与订单阶段沿用本页。

## 订单阶段

`PlayerTroopOrderStage`：`None=0`、`Training=1`、`Delivering=2`。`GWPP_PlayerTroopOrderComposition` 存各兵种与人数，`GWPP_PlayerTroopOrderStockTroopId` 存调货对应兵种，`GWPP_PlayerTroopOrderPriceUnits` 存精确声望。旧档从兵种、数量和原付款字段续办。（依据：用户裁定 2026-11-15；旧档兼容设计）

- 有在办订单时不能再下新单；士兵派遣下单另要求没有在途练兵使者。订单卡住会连带
  让这些入口消失。
- 已知缺陷：存档里的订单组合含有不在可订名单或已找不到的兵种 id 时，组合解析为空但阶段仍是在办，心跳不推进、交付对话不出现、也不能下新单，订单永久卡住。只在坏档或兵种 id 变更时触发；按不做读档补正的原则未处理。（依据：独立审查 2026-11-15）
- 会员在同一页给六种灰袍兵分别填写人数或用加减按钮。可任意混搭，按[实际阶级](warden-recruitment.md#兵员阶级的声望折算)精确合计，去掉按声望解锁兵种和固定数量档。登记时按扣款后余额核对[主队额度](warden-recruitment.md#玩家兵源与声望方案)，使者送达也核对。接兵时按当时的余额核对，名额不足则保留已备齐的订单，事务标为等待名额。（依据：用户裁定 2026-11-14、2026-11-15；报价和接收复核设计）
- 每小时清点随行练兵队，未建队时数练兵官；各项均按健康人数。缺额按阶级从高到低调货和训练，练兵官备齐所有订单兵种才前往玩家处一次交齐。（依据：用户裁定 2026-11-15；本轮训练与交付设计）
- 已有订单阻止后来求援征调该练兵官；订单执行仍查询 `GwpWardenDuties.BlockingDuty(练兵官, PlayerRequest)`，已有的有效高优先级差事结束后继续。具体准入与后台约斗交接只在[灰袍 AI](warden-ai.md)的差事归属表维护。订单快照带 `PausedBy`，事务页据此显示等待原因。（依据：源码复核；离线回归 test_duty_priority、test_player_order_status 2026-10-18）
- 当面确认即登记，使者送达后才登记；两条入口统一在登记时扣一次灰袍声望，交付对话沿已付账目结算，账簿按实际币种显示。使者出发时只携订单。取消选择或使者未能登记都不会扣声望；取消已登记的订单沿原取消规则，已付费用不退，士兵留给练兵官。旧档已登记订单继续交付，旧在途使者仍按已带金币履约或带回，只会完成原付款。（依据：用户裁定 2026-11-15；既有取消规则 2026-10-21；兼容口径与扣款时机为本轮实施）

## 随行练兵队

- 订单的兵装在无领主的随行练兵队里，跟随练兵官；练兵官手上至少留
  `CohortTrainerFloor = 15` 人。队伍丢失时重新拉起并提示玩家“路上折了”；
  空队会被原版清除，所以练兵官无人可拨时不建队。
- 练兵队优先补各项已有的健康成品，再为当前缺项补可升成目标的低阶兵或可拆编重训的高阶兵。超额或用不到的兵连伤情、经验退回练兵官，补员与退回受 15 人留队和随行队不清空的约束。战后收进来的外来兵回练兵官队后走[领主纯化](warden-recruitment.md#纯化)。（依据：2026-11-15 混合订单补员实现）
- 每 6 小时按每名可训练兵加 1000 经验。兵源不足时每次最多拆编重训四名下游兵，成品预留人数计入扣除。升级继续由原版升级器执行。（依据：原有节奏；混合订单预留设计）

### 练兵队的照看不经过练兵官门禁

`TendCohort` 每小时都跑，在 `TryReservePartyForPlayerRequest` **之前**：续跟随（8 小时意图）、
压侵略性（`AttackInitiative = 0.2`，2 小时）、`TopUpCohort` 双向换兵。练兵官或练兵队任一方
在战斗中时只续跟随和侵略性，不动名册，打完再换。建队、调货、加经验、送货仍在门禁之后。
练兵队不吃饭，见 [temporary-parties.md](temporary-parties.md)。

- 练兵队会跟练兵官一起打劫匪：`Aggressiveness` 是原版默认 1，敌方正和同阵营队伍交战时原版
  进攻分被抬高（`DefaultMobilePartyAIModel`）。用户接受参战，战后收进来的
  外来兵由 `TendCohort` 退回练兵官。欲望系统不改（用户裁定 2026-09-25）。

原版跟随（`MobilePartyAi.GetFollowBehavior`）：被跟随方在定居点里 → 跟进去；
被跟随方失效 → 原地 `Hold`；被跟随方在海上而自己没船 → 停在岸边。原版不销毁城里的无领主
自定义队；我们对纠察队、延迟纠察队有"进城即销毁"，对练兵队没有。（依据：C#反编译 v1.4.8 `DefaultMobilePartyAIModel`、`MobilePartyAi.GetFollowBehavior`；用户裁定 2026-09-25）

| 练兵官状态 | 练兵队 |
|---|---|
| 进城 | 跟进城，照常换兵 |
| 在战斗中 | 续跟随；可能参战；打完退回外来兵 |
| 在军团里 | 照常跟随、换兵（门禁关着，但照看不经过门禁） |
| 战败被俘 | `ResolveTrainerParty` 为空，无人照看，意图过期后交还原版 AI 游荡；不吃饭所以不会饿伤。英雄获释重建队伍后恢复 |
| 值守人换人 | 下一拍改跟新练兵官 |
| 在海上、练兵队没船 | 停在岸边等 |

订单结束解散练兵队时，练兵官缺席则人交给最近的灰袍领主（`FindNearestGreyWardenLordParty`），
不清空名册。

## 升级、账簿与调货

- 可升到当前缺项的兵只有通向该项的分支有权重；混合订单没有练兵队时同样作用于练兵官本人。0 权重拦不住原版只有一个升级目标或全部为 0 时取第一个，所以单兵种与混合订单都在当前名册预留每项健康成品；有练兵队时，练兵官手上再预留补足练兵队缺额所需的成品。预留内的兵不可升级，原版可升人数最多使用预留之外的健康兵。（依据：独立审查与 PartyUpgraderCampaignBehavior.SelectPossibleUpgrade 源码 2026-11-15）原版批量入口见[部队页升阶](../vanilla/party-screen-upgrades.md#怎么运作)。（依据：v1.5.7 源码与混合订单设计 2026-11-15）
- 已知缺陷：开着 RBM 且启用缴获池时，RBM 用自己的升级入口整段替换原版 GetPossibleUpgradeTargets，部分预留补丁不生效，只剩「预留外为 0 时整种锁住」；混订前后阶（如新兵加重步兵）时预留的低阶成品可能被升走、订单回退。按不主动适配第三方玩法、不挂钩 RBM 私有方法的规则未处理（见[与其他模组共存](infrastructure.md#与其他模组共存)）。（依据：独立复核与本机 RBM 4.5.4 反编译 2026-11-15）
- 账簿、完成判定与交付共用同一名册。各项就绪数最多计该项订购量，账簿显示组合和合计进度。（依据：混合订单设计 2026-11-15）
- **调货** `AdvanceStockCollection` 的“已够数”判定与 `ExchangeStockAtRendezvous` 的缺额，
  都按 `CountOrderedOnHand` = 练兵官健康目标兵 + 练兵队健康目标兵。

## 海上

随行练兵队出生时向练兵官借真船（按订单人数），解散时退回；练兵官在海上又借不出船时先不建练兵队，
订单暂用练兵官名册。见 [temporary-parties.md](temporary-parties.md)。
**练兵官是领主，不送船**，靠原版购船与海战缴获获得船只（见 temporary-parties.md）；
恰好无船时，玩家在海上仍收不到交付，要等玩家上岸。

# 玩家练兵订单与随行练兵队

> 当前状态：当面及使者共用混合兵种订单页；练兵队改为成品仓、原料在练兵官手上练，调货退休，待实测
> 最后验收：`03964e4`（v1.4-r13 构建；2026-09-26 用户确认）
> 覆盖源码：`GreyWardenTroopRequestBehavior.cs` `GreyWardenTroopRequestBehavior.Cohort.cs` `GwpTroopOrderScreen.cs` `GreyWardenPolicePurity/Core/Troops/TroopOrderComposition.cs` `PolicePartyTroopUpgradeModel.cs`
> 待实测：当面和使者混合下单、精确扣除小数声望、取消和名额不足；练兵队成品不再升级（含 RBM 缴获池），前后阶混订保留低阶成品；练兵官练成指定兵种、原料不足时拆编重训和跨分支降级；旧订单与同版混合订单存读、一次交齐和练兵队归还伤兵与经验

本文件只写玩家向灰袍练兵官订兵这条线。练兵官挂名与全队兵种配比取向
（`GreyWardenTrainingBehavior`）见[日常练兵](warden-training.md)。共用升级模型新增的守村灰袍付款选择只在信众村民兵升级范围生效，不改变订单锁定、交付或分支；费用归属见[村庄](firesworn-villages.md)。订单只占用练兵官本人，不向别的灰袍领主调货。自主运兵不占用领主、不取消订单，规则见[运兵](warden-training.md)。（依据：源码复核 2026-10-09；用户裁定、源码复核 2026-10-15）

兵员搬运及建队编号规则只在 [临时队](temporary-parties.md) 定义，选兵与订单阶段沿用本页。

## 订单阶段

`PlayerTroopOrderStage`：`None=0`、`Training=1`、`Delivering=2`。`GWPP_PlayerTroopOrderComposition` 存各兵种与人数，`GWPP_PlayerTroopOrderPriceUnits` 存精确声望。旧档从兵种、数量和原付款字段续办；旧档里的调货与升级锁存档键读档时被原版忽略。（依据：用户裁定 2026-11-15；旧档兼容设计）

- 有在办订单时不能再下新单；士兵派遣下单另要求没有在途练兵使者。订单卡住会连带
  让这些入口消失。
- 已知缺陷：存档里的订单组合含有不在可订名单或已找不到的兵种 id 时，组合解析为空但阶段仍是在办，心跳不推进、交付对话不出现、也不能下新单，订单永久卡住。只在坏档或兵种 id 变更时触发；按不做读档补正的原则未处理。（依据：独立审查 2026-11-15）
- 会员在同一页给六种灰袍兵分别填写人数或用加减按钮。可任意混搭，按[实际阶级](warden-recruitment.md#兵员阶级的声望折算)精确合计，去掉按声望解锁兵种和固定数量档。登记时按扣款后余额核对[主队额度](warden-recruitment.md#玩家兵源与声望方案)，使者送达也核对。接兵时按当时的余额核对，名额不足则保留已备齐的订单，事务标为等待名额。（依据：用户裁定 2026-11-14、2026-11-15；报价和接收复核设计）
- 每小时清点随行练兵队，各项均按健康人数；没有练兵队时订单原地等，不算备齐。缺额按阶级从高到低逐项训练，练兵队备齐所有订单兵种后练兵官才前往玩家处一次交齐。不向别的灰袍领主调货：练兵官把成品拨走、队伍变小后，原版会照常去招兵补回原料。（依据：用户裁定 2026-11-15）
- 已有订单阻止后来求援征调该练兵官；订单执行仍查询 `GwpWardenDuties.BlockingDuty(练兵官, PlayerRequest)`，已有的有效高优先级差事结束后继续。具体准入与后台约斗交接只在[灰袍 AI](warden-ai.md)的差事归属表维护。订单快照带 `PausedBy`，事务页据此显示等待原因。（依据：源码复核；离线回归 test_duty_priority、test_player_order_status 2026-10-18）
- 当面确认即登记，使者送达后才登记；两条入口统一在登记时扣一次灰袍声望，交付对话沿已付账目结算，账簿按实际币种显示。使者出发时只携订单。取消选择或使者未能登记都不会扣声望；取消已登记的订单沿原取消规则，已付费用不退，士兵留给练兵官。旧档已登记订单继续交付，旧在途使者仍按已带金币履约或带回，只会完成原付款。（依据：用户裁定 2026-11-15；既有取消规则 2026-10-21；兼容口径与扣款时机为本轮实施）

## 随行练兵队

- 随行练兵队是成品仓：无领主，跟随练兵官，只装练成的订单兵，整队不升级。练兵官手上至少留
  `CohortTrainerFloor = 15` 人。队伍丢失时重新拉起并提示玩家“路上折了”。
  空的无领主队打完仗会被原版销毁，误报成“路上折了”，所以练兵官手上有成品、留够 15 人还能拨出去时才建队；没有练兵队时照样在练兵官手上练，只是交不了货。（依据：用户裁定 2026-11-15；v1.5.7 MapEventSide 战后清理 0 人参战队）
- 每小时先把练兵官手上练成的订单兵拨进练兵队，补到各项订购量；超出订购量的和不是订单兵种的连伤情、经验退回练兵官，伤兵先退。补员与退回受 15 人留队和练兵队不退空的约束。战后收进来的外来兵回练兵官队后走[领主纯化](warden-recruitment.md#纯化)。（依据：用户裁定 2026-11-15）
- 原料留在练兵官手上练：每 6 小时把能沿升级树练成当前缺项的灰袍兵的经验补到「还差人数 × 朝目标升一级的经验」，是补足不是累加（升级器一天只跑一次，累加会一天升出好几倍的人），离目标近的兵种先补；别的订单项还要拨走成品的那叠暂不加经验，但判断要不要拆编重训时，它超出预留的人仍算原料。练兵官手上能练成当前缺项的兵升向它时不收练兵官的金币，订单已由玩家付过声望；RBM 缴获池开启时 RBM 用自己的价格，这条不生效。原料不够时拆编重训，每次最多四名：目标的下游直接降成目标；别的分支（如要弓手、手上只有骑士）降到共同上游再练，先降离目标最近、阶级最低的；别的订单项还要拨走的成品不拆。升级仍由原版或 RBM 的升级器执行。（依据：用户裁定 2026-11-15；独立审查 2026-11-15）

### 练兵队的照看不经过练兵官门禁

`TendCohort` 每小时都跑，在 `TryReservePartyForPlayerRequest` **之前**：续跟随（8 小时意图）、
压侵略性（`AttackInitiative = 0.2`，2 小时）、`TopUpCohort` 拨入成品和退回多余。练兵官或练兵队任一方
在战斗中时只续跟随和侵略性，不动名册，打完再换。建队、加经验、拆编重训、送货仍在门禁之后。
练兵队不吃饭，见 [temporary-parties.md](temporary-parties.md)。

- 练兵队会跟练兵官一起打劫匪：`Aggressiveness` 是原版默认 1，敌方正和同阵营队伍交战时原版
  进攻分被抬高（`DefaultMobilePartyAIModel`）。用户接受参战，战后收进来的
  外来兵由 `TendCohort` 退回练兵官。欲望系统不改（用户裁定 2026-09-25）。

原版跟随（`MobilePartyAi.GetFollowBehavior`）：被跟随方在定居点里 → 跟进去；
被跟随方失效 → 原地 `Hold`；被跟随方在海上而自己没船 → 停在岸边。原版不销毁城里的无领主
自定义队；我们对纠察队、延迟纠察队有"进城即销毁"，对练兵队没有。（依据：C#反编译 v1.4.8 `DefaultMobilePartyAIModel`、`MobilePartyAi.GetFollowBehavior`；用户裁定 2026-09-25）

| 练兵官状态 | 练兵队 |
|---|---|
| 进城 | 跟进城，照常换兵 |
| 在战斗中 | 续跟随；可能参战；打完退回外来兵 |
| 在军团里 | 照常跟随、换兵（门禁关着，但照看不经过门禁） |
| 战败被俘 | `ResolveTrainerParty` 为空，无人照看，意图过期后交还原版 AI 游荡；不吃饭所以不会饿伤。英雄获释重建队伍后恢复 |
| 值守人换人 | 下一拍改跟新练兵官 |
| 在海上、练兵队没船 | 停在岸边等 |

订单结束解散练兵队时，练兵官缺席则人交给最近的灰袍领主（`FindNearestGreyWardenLordParty`），
不清空名册。

## 升级与账簿

- 练兵队整队锁升级：升级模型的 `IsTroopUpgradeable` 对练兵队返回 false。原版升级器和 RBM 缴获池的升级入口都先问这一项，所以不需要按人数预留，也不挂钩任何升级器。（依据：v1.5.7 PartyUpgraderCampaignBehavior 与本机 RBM 4.5.4 SpoilsUpgradePatches 反编译 2026-11-15）
- 练兵官手上能练成当前缺项的兵只有通向该项的分支有权重，原版与 RBM 都按升级模型的分支权重选分支；其余兵由[升级取向](warden-training.md#全灰袍部队的升级取向)决定，有可练原料时取向钉在订单兵种的编队上。练兵官手上还没拨进练兵队的成品（15 人留队或还没建队时会等一阵）整叠锁升级，拨够后解锁，这叠剩下的兵照常当原料。原版批量入口见[部队页升阶](../vanilla/party-screen-upgrades.md#怎么运作)。（依据：用户裁定 2026-11-15）
- 账簿、完成判定与交付都只认练兵队。各项就绪数最多计该项订购量，账簿显示组合和合计进度。（依据：混合订单设计 2026-11-15）
- 已知缺陷：开着 RBM 缴获池时，RBM 按缴获和金币截断有领主部队的升级人数，各分支价格按装备价差不同（离友方城镇远时只认缴获），通往目标的分支（尤其最贵的骑士）可能被剔除；剩下的分支权重都是 0，RBM 取第一个，灰袍兵被升成重步兵，又被拆编重训拆回，循环烧缴获。原版各六阶分支同价，没有这个问题。按不主动适配第三方玩法的规则未处理（见[与其他模组共存](infrastructure.md#与其他模组共存)）。（依据：独立审查与本机 RBM 4.5.4 SpoilsUpgradePatches 反编译 2026-11-15）

## 海上

随行练兵队出生时向练兵官借真船（按订单人数），解散时退回；练兵官在海上又借不出船时先不建练兵队，
订单原地等上岸。见 [temporary-parties.md](temporary-parties.md)。
**练兵官是领主，不送船**，靠原版购船与海战缴获获得船只（见 temporary-parties.md）；
恰好无船时，玩家在海上仍收不到交付，要等玩家上岸。

## 当前方向

- 这是玩家参与灰袍宗教组织的统一入口；成年灰袍均按本职履职。具体成员/本职继承归[家族](family.md#本职)。（依据：用户裁定 2026-10-18）
- 用户提议过合并商队护卫与护村，但随后明确暂缓职业调整，按当前六职能先实现界面；本轮不合并职业、不补第七个职能。请愿与重建的重要性、请愿的收入来源地位不因界面调整而改变。（依据：用户裁定 2026-10-18）
- 领取委托直接进入职能案件列表，由玩家挑选；重点为预计能赚多少、敌人当前在哪、目标强度，案发地在次要记录。（依据：用户裁定 2026-10-18）
- 地图导航入口要求已入会且声望≥20；灰袍家族百科页按钮保留为彩蛋，不受入会和声望门槛限制。彩蛋只开放查看事务，接案等业务资格仍由各自入口检查；不新增负声望/通缉/赎罪面板。（依据：用户裁定2026-10-18，明确家族页例外）

## 自选案件

- “挑选案件”切到职能事务中最近可领案件所属职能；不另开三选一或合同弹窗。
- 列表显示现有商队袭击/村庄暴力开放卷宗；全部合资格案件都可挑选，不再截成最近/较难/较易三条。
- 商路/乡土列表先排案件，再排同职能的其他工作；案件按罪犯当前部队距玩家主队的直线地图距离升序，同距按稳定CrimeId次序，暂未解析活跃部队者排后。不按收益、强弱或是否可领分先后，已有人追捕的案件同样显示双方头像与办理进度。不可接的开放卷宗仍可查看，没有接受按钮。（依据：用户裁定与实现2026-10-18）
- 主详情顺序：摘要中的预计办案费、目标现所在地、己方/目标战斗组战力、目标本队总人数/健康人数、所在编组、应缴罚金上限与既有承办阶段。旧案发位置/时间及估计酬劳说明在案情记录节，交涉结果在近期交涉回报节。
- 当前所在地使用目标此刻部队：在城镇、城堡、村庄里显示该聚落名；在野外或藏身处等特殊地点时，用共享的 `GwpCommon.FindNearestSettlement` 在城镇、城堡、村庄里取最近一座，显示“某某附近”，不拿案发地充当现位置。旧的最近聚落查询漏了城堡，离城堡更近的人会被说成在村庄附近。（依据：用户反馈2026-10-18；GwpCommon.IsOrdinarySettlement 修正）
- 强度统一读取`GwpStrength.CaseTarget`/`CombatGroup`；难度复用既有阈值。本队人数与战斗组战力分别标示，军团/围城营合并口径不伪装成目标本队人数。强度是当前快照，不保证路上敌方不会改变编组。
- 预计个人办案费复用`GwpCaseSettlementRules.Reward(当前罚金上限, 0, 当前罪责点)`，不是应缴罚金；无新增阵亡的估计，实际赔偿、交付和抚恤仍走原结算。（依据：用户关注收入；原结算源码复核2026-10-18）
- 接受时在PlayerBountyBehavior重新读取共享候选池，检查实时资格、目标、开放状态、使者约定、罚金和预计办案费。旧条目变化就刷新，不接受过期合同。成功后转我的事务显示该委托；原接单事务负责占案、释放NPC承办、任务日志、期限与后续交差。
- 资格、占案和完整业务规则仍归[玩家入会与悬赏](player-justice.md#悬赏接单)，界面不另写判断。（依据：共享概念归属流程）

当前委托被第三方扣押时摘要显示实际扣押者和扣押队/地牢地点；逃亡或暂失队时显示失去踪迹及等待/撤回说明，不列旧部队位置和战力。仅符合共享未完成门槛的当前委托显示无责撤回按钮，确认后刷新、原案保留；其他分类没有撤单按钮。业务与回退归[玩家委托](player-commission.md#目标不可追踪时的无责撤回)。（依据：用户裁定、生产与VM回归2026-10-21）

## 玩家与办案使者

当前委托记录只显示一次，选中它时详情内有派使者复命、派使者求援两个具体动作，各自沿原归属方资格显示禁用原因。选中支援或使者记录只看该记录详情，不混入另发委托/撤回动作；原委托结束后仍在途的返程使者保留可见。订单、讲和、封地各页即使没有记录也保留本业务派遣按钮。按钮固定240×40、22号字、左对齐，在详情滚动区，不挤入底部百科/接案/军械操作区。（依据：用户分类反馈、实现设计2026-10-21）

列表按结构化DispatchPurpose分流，不从显示文字判断：当前委托含委托、支援及复命/求援使者；订单、讲和、封地分别含自身实际事项和同目的使者。无当前委托时默认打开最近在途目的的业务分类，空委托保留领任务入口，不能凭空复命/求援。（依据：设计与完整VM66断言2026-10-21）

资格、MapState衔接、原选兵/付款/交割和存读边界由[送信队](dispatch.md#开口我的事务或本队灰袍兵)维护；界面只发起具体目的，不新增资源或替代交付。（依据：共享归属设计2026-10-21）

- 玩家使者归我的事务：复命、求援、送练兵订单、请求调停四种目的，显示去程/返程、收件领主、当前位置、兵员/健康人数、实际金币/俘虏/物品、出发时间，以及途中卖俘虏/待交割等已有状态。
- 送订单/求援未送达时只显示递送中；正式成立的订单/受援从各业务状态查询，不能因展示新增一笔订单或支援。（依据：现有送信/订单业务）
- NPC向罪犯派出的办案使者不是玩家使者。进行中的交涉/协力暂停是当前案件的承办进度；历史交涉回报不生成案件、待办或成员当前任务。成员当前工作仅读真实Assignee对应任务的办理进度，不复制玩家可赚收益和敌方战力；近期交涉回报按WardenHeroId归本人，显示时间、对象和实际结果/金额，已结案的仍可在该成员的回报节查看。开放案详情也可查看关联交涉结果，没有独立回报顶级分类。回报只分“交涉达成”和“交涉未成”两种，后面跟一个短原因；使者途中失踪算交涉未成。（依据：用户裁定2026-10-18）（依据：用户反馈与实现2026-10-18）
- 玩家的练兵订单被后来送达的求援、玩家案件或约斗占住练兵官时，订单状态显示等待哪一项结束（等待支援结束/等待执法任务结束/等待比武结束），已备人数不超过订单人数；该成员详情把订单列在“待办事项”而不是当前工作。先后规则仍归[练兵订单](troop-orders.md#订单阶段)。（依据：用户反馈2026-10-18：练兵与求援落到同一领主，显示像同时在做两件事）
- 周期接单招揽、两层选单、冷却、通知存档类型已随替换删除；不再每两天刷“无案件”或右侧招揽。已承接任务的情报、战斗结果、交割和真实险情通知保持现有业务。（依据：用户允许收束接单噪音；实现2026-10-18）

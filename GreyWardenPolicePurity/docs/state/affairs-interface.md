## 当前方向

- 这是玩家参与灰袍宗教组织的统一入口；成年灰袍均按本职履职。具体成员/本职继承归[家族](family.md#本职)。（依据：用户裁定 2026-10-18）
- 用户提议过合并商队护卫与护村，但随后明确暂缓职业调整，按当前六职能先实现界面；本轮不合并职业、不补第七个职能。请愿与重建的重要性、请愿的收入来源地位不因界面调整而改变。（依据：用户裁定 2026-10-18）
- 领取委托直接进入职能案件列表，由玩家挑选；重点为预计能赚多少、敌人当前在哪、目标强度，案发地在次要记录。（依据：用户裁定 2026-10-18）
- 界面按已入会且声望≥20的玩家开放，不设计负声望/通缉/赎罪面板；负声望执法业务本身仍由原系统处理。（依据：用户裁定 2026-10-18）

## 自选案件

- “领取委托：查看案件”切到职能事务中的案件职能，有可领案时优先落到有候选的一类；不另开三选一或合同弹窗。
- 列表显示现有商队袭击/村庄暴力开放卷宗；全部合资格案件都可挑选，不再截成最近/较难/较易三条。
- 可领案件排前，其后按预计个人办案费降序、目标本体战斗组强度升序、稳定CrimeId次序。不可接的开放卷宗仍可查看，没有接受按钮。
- 主详情顺序：预计办案费、目标现所在地、己方/目标战斗组战力、目标本队总人数/健康人数、所在编组、应缴罚金上限与既有承办阶段。旧案发位置/时间和使者回报在其他记录里。
- 当前所在地使用目标此刻部队：在聚落时显示真实聚落名；野外显示最近城镇附近，文字明确是附近，不拿案发地充当现位置。
- 强度统一读取`GwpStrength.CaseTarget`/`CombatGroup`；难度复用既有阈值。本队人数与战斗组战力分别标示，军团/围城营合并口径不伪装成目标本队人数。强度是当前快照，不保证路上敌方不会改变编组。
- 预计个人办案费复用`GwpCaseSettlementRules.Reward(当前罚金上限, 0, 当前罪责点)`，不是应缴罚金；无新增阵亡的估计，实际赔偿、交付和抚恤仍走原结算。（依据：用户关注收入；原结算源码复核2026-10-18）
- 接受时在PlayerBountyBehavior重新读取共享候选池，检查实时资格、目标、开放状态、使者约定、罚金和预计办案费。旧条目变化就刷新，不接受过期合同。成功后转我的事务显示该委托；原接单事务负责占案、释放NPC承办、任务日志、期限与后续交差。
- 资格、占案和完整业务规则仍归[玩家入会与悬赏](player-justice.md#悬赏接单)，界面不另写判断。（依据：共享概念归属流程）

## 玩家与办案使者

- 玩家使者归我的事务：复命、求援、送练兵订单、请求调停四种目的，显示去程/返程、收件领主、当前位置、兵员/健康人数、实际金币/俘虏/物品、出发时间，以及途中卖俘虏/待交割等已有状态。
- 送订单/求援未送达时只显示递送中；正式成立的订单/受援从各业务状态查询，不能因展示新增一笔订单或支援。（依据：现有送信/订单业务）
- NPC向罪犯派出的办案使者不是玩家使者。其进度/协力暂停在案件详情，最近交涉回报附案件次要记录；无开放案的现存短期回报归原案类别的最近记录，没有独立回报顶级分类，也不补造完整结案史。
- 周期接单招揽、两层选单、冷却、通知存档类型已随替换删除；不再每两天刷“无案件”或右侧招揽。已承接任务的情报、战斗结果、交割和真实险情通知保持现有业务。（依据：用户允许收束接单噪音；实现2026-10-18）

## 数据归属与存读

- UI条目保存稳定ID、类型/本职、人物/地点引用、原始业务字段；旧台账的详细业务格式器保留为GwpCaseArchiveItemVM。不从显示字符串解析人物、职责或阶段。
- 案件归CrimePool，协力/办案使者归PoliceEnforcementBehavior；个人委托/受援归PlayerBountyBehavior，玩家使者归GwpWardenDispatchBehavior，待调停归PoliceAntiWarDeclaration。
- 善后、重建、请愿、练兵、订单与申诉使用各自GetTaskSnapshots。按业务本职归类，不因当前临时协助者换职业而移动案件分类。
- 成员本职读取GreyWardenFamilyBehavior；头像为CharacterImageIdentifierVM。教务仅读取GwpFireswornBehavior的村庄、仪式和库存查询，不新增宗教等级、远程仪式或玩家指挥权限。
- 打开/主动刷新取快照，切页不逐帧扫全局。屏幕期间保留各页选中类别及稳定条目ID；刷新时选中已消失则选首条有效记录。次要记录默认折叠，当前不持久化滚动偏好。
- 界面快照、选择和焦点不进战役存档：它们不代表进行中的工作，可由原有业务存档重建；委托、玩家使者、订单、仪式仍由原归属方保存，同版本读档接续。（依据：用户存档裁定；实现设计）

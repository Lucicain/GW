# 立即追截队：归队与多余的人

> 当前状态：首次宣战与首支追截准备合并，分兵后不占优则不宣战；无速度门槛及动态补派保护保留，已部署
> 最后验收：2026-10-18 用户正常跟随未见异常；本轮日志确认49次8人追截与实际补派，仍有兜底判定待处理
> 覆盖源码：`PoliceEnforcementBehavior.cs` `PoliceEnforcementBehavior.DelayPatrols.cs` `PoliceEnforcementBehavior.WarPursuitTrace.cs` `tools/Verify-EnvoyNavigation.ps1` `tools/tests/test_case_interceptors.py`
> 待实测：正常游玩中首队准备失败不宣战、准备成功同轮宣战/出队，以及无速度门槛补派和战力变化后停派；周期兜底旧缺陷另待收束，不要求专项挂机

追截队、使者不算协力编队的在编力量，不靠它们保留军团（见 [案件](case-enforcement.md)「协力编队」）。
案件本身的生命周期见 [案件](case-enforcement.md)；船怎么借、怎么还见 [临时队](temporary-parties.md)。
[灰袍使者](case-envoy.md) 的出队（`CreateDetachment`、`DetachmentBatches`）和归队与追截队同一套；
使者归队时另把带回的钱交进公库、把投案的罪犯交给主队。

派队的玩家目标避让统一查 `GwpPlayerCaseAssignment.IsReservedTarget`，同时包括普通悬赏与赎罪；交接规则见[赎罪](atonement.md)和[使者](case-envoy.md)。（依据：源码复核2026-10-15）

立即追截队（`TrySpawnImmediateCaseInterceptor`）的人是从来源领主名册里抽出来的。返程时
先还来源领主；来源领主战败、被俘或队伍没了（`CanContinueLeadingPoliceTask` 为假），改交最近的
灰袍领主（`GwpCommon.FindNearestGreyWardenLordParty`），并把接收人写回
`DelayPatrolState.SourceTaskPolicePartyId`，之后不再换人。只有返程状态会改接收人，
承办中的重定目标冷却（只看未返程的队）不受影响。

到达交接距离后，双方上下船均已结束、没有待执行的港口登船且海陆侧一致，才完成交接；否则保留船、人、钱及返程状态，继续原有归队流程。只看IsCurrentlyAtSea会把未完成的登船误作已在陆上，原版到时完成登船时仍可变成海上无船。（依据：实际游戏DLL离线复现、C#反编译2026-10-18）

碰到接收的主队时（用户裁定 2026-10-14：追截队必须回到主队，不带着船去城里解散）：
- 船当场交回主队（`PoliceResourceManager.ReturnLentShips`）；在海上还要靠船走，留到解散时再还。
- 在陆上：先全部并回主队，再把主队里最低阶的人拿出去（同阶的原版兵先走），拿出去的人数不超过这次回来的人数、只到主队满编为止，
  主队留下精锐。（依据：用户裁定 2026-10-15）
- 在海上：没法下船，只回装得下的，灰袍兵先回；剩下的带着船去信众村，到了解散时船还给出借方。（依据：用户裁定 2026-10-14；10-15 确认海上这样就对）
- 普通俘虏全部交给主队，使者押回的投案者也交给主队。
- 拿出来或装不下的人走到最近的信众村（有祭司、安静、不与灰袍交战），在那里落脚：灰袍兵进守村队、非灰袍兵进原版民兵、
  俘虏进地牢、钱进公库（`GwpFireswornBehavior.SettleInFaithVillage`，与火誓者无领主队落村同一段处理，见 [队伍](firesworn-parties.md)）。
  一座能去的信众村都没有时才进最近的城解散。一位能接收的灰袍领主都没有时，整队照旧进城解散。

追截队被目标掉头吃掉后马上再派、不设冷却，是对的。（依据：用户裁定 2026-10-14）

## 追截与主队接战

追截队的用途是在案件宣战后先发起接战、拖住目标，给主队按原版AI赶上接战的机会；不能把区域3距离视作AI自动参战触发器。玩家遭遇的附近援军收集和AI主动接触加入战斗是不同入口，详见[协力](case-assistance.md#区域宣战与持续接战)。（依据：用户说明2026-10-18、2026-10-20批准；原版C#反编译）

普通单队案件与协力主办在每小时UpdateTasks中统一检查追截；已宣战、仍在WarPursuit的普通案不再要求本小时宣战快照或协力组。现有有效追截队只保留一支；已移除或健康人数为0的旧队不阻挡补派，没有冷却。驻城、使者未决、玩家占案、差事暂停、现场区域力量、原主队军团资格与可借船条件继续从现有归属方核对。（依据：用户裁定2026-10-14；源码与生产方法回归2026-10-18）

追截仍从本队和实际挂靠协办抽取3～8名真实健康非英雄兵；骑兵优先，不足时按现有灰袍身份、阶级、来源顺序补其他兵，不再仅限灰袍骑兵。不比较主队/小队与目标速度，不因小队理论速度不占优销队；兵员、装备与原版移动速度不加速，使者的既有混编选兵顺序保持。原长局第二队4人的原因就是当时只有4名健康灰袍骑兵，而非主队只有4名可用兵。（依据：用户裁定、生产方法回归2026-10-18）

已派出的追截队只持续直攻目标，不强逐城内目标；原版驻城接触规则见[案件](case-enforcement.md#藏城目标与战后连续交战)。（依据：生产直攻命令与原版接触入口8项回归 2026-10-19）

主队宣战后继续交给原版欲望和短期AI选择接战；追截队不按目标速度拒派，用于让目标先进入战斗，主队未及赶到时以补派追截继续拖住。不能据第一场约1小时的短窗口就把原版欲望判为本次代码缺陷；本次修复目标是普通追截的持续补派，不改变主队命令。（依据：用户明确2026-10-18）

## 常规追截与战力复核

首次自主案件与玩家支援宣战已对应首队实际可出动条件：同次同步调用先真实建队/抽兵/配给并复核，成功后才宣战并发布追击；失败退回资源、继续原未宣战跟随。略占优但不足以按现有兵源规则分出首队时暂不因本案宣战，不擅自扩大协力征调，也不修改主队原版欲望或增加猜测比例。玩家支援只有新宣战成功才收到开战通知。（依据：用户问题、实现与离线执行2026-10-20）

主队宣战后继续利用原版欲望和短期AI灵活行动，不改原版进攻评分或强迫主队冲锋。立即追截不再以主队或小队与目标速度比较作派出条件；敌人增长或主队损耗使当前原版区域不占优时停止新派/补派，抽兵后再次排除新小队复核，不能沿用宣战时的旧优势持续送兵。取消两处速度拒派已部署。（依据：用户批准与风险要求2026-10-20）

TryDeclareCaseWarWithInterceptor先区分实际外交：若同一势力已在交战，只登记本案到既有战争、保留结果结算并尝试安全派队，不把这当成新开战；玩家支援照常得到参战通知。若尚未交战，才要求首队准备成功后提交新战争。两条路径补派都保留当前区域门槛，不能因首队失败擅自清掉其他案件的战争。（依据：既有战争接续与专项62断言2026-10-20）

TrySpawnImmediateCaseInterceptor的declareWar模式只用于首次自主/玩家支援宣战；普通补派不再次宣战。首队准备成功后才同步DeclareWar、刷新原版思考及发布小队追击，未引入跨小时准备状态或存档键。已有有效同案追截可复用，仍先检查当前区域许可；已开战目标换势力的外交接续保持原有ReconcileTaskWarStatesWithDiplomacy规则，不随本次首次宣战调整中断在途战斗。已有存档中的战争不自动清空。（依据：源码与同版本接续要求2026-10-20）

每次首派/补派都重新调用CanInitiateCaseAttack及原版区域计算，只有仍可攻击才抽兵；实际配兵/借船后再次检查主队优势，失败完整退兵还船销队。现有同案有效追截仅一支，已派出的队伍沿旧追击与交接规则继续，不因这次更新新增瞬移召回或删除在途队。主队开始战斗后不再派新立即追截，驻城/差事/玩家占案等既有门槛保留。（依据：用户风险要求、生产入口复核与离线执行2026-10-20）

原版对近距离之外的移动目标，在缓存基础速度差≤0.01时仍可给进攻0；区域优势本身不保证主队主动进攻，也不保证任意小队都能追上目标或撑到主队入场。（依据：本机v1.4.8原版执行 2026-10-20）

## 周期兜底的定位与当前缺口

普通周期支援在没有协力军团时独立追敌；已有因敌强而组建的合法协力军团时，可以入团并计入实际战力。立即追截队保持独立。不能因影响力异常就排除普通支援入团；本轮误解该定位产生的未部署业务改动已撤回。（依据：用户裁定2026-10-19）

周期50人队的目标是异常停滞时兜底拖住目标；应尽量避免正常流程落到兜底，不能把兜底出现视作正常追捕已经无问题。（依据：用户裁定2026-10-18）

已知缺陷：两日扫描仅查已承办开放案件、WarPursuit和外交仍交战，没有确认真正无进展；不排除目标驻城、主队正在后勤、已有追截/支援在途或交战，也没有单案数量上限，因此正常未结案也会反复派50人。周期是全局两日，不是每宗案宣战满48小时；本轮只分析并补诊断，尚未改触发规则。（依据：用户目标、源码与长局2026-10-18）

当前没有足够证据把主队后勤与追截抽兵列为独立的已证实故障：19:17旧局早于原版区域门槛统一，不能证明修复后同条件追捕仍失效。判定时序见[地图AI](warden-ai.md#欲望竞价)，原版接触边界见[藏城目标](case-enforcement.md#藏城目标与战后连续交战)。（依据：当前源码、本机原版执行与旧局切片复核 2026-10-19）

SpawnSingleDelayPatrol在诊断编译分支增加DELAY_SUPPORT_DEPLOYED，记录实际队号、目标、来源、人数、two_day_scan、目标聚落/战斗及来源缓存访村分；复用队号和借船旁证不足以精确统计历史50人派出次数。调查闭合时退休该记录；常规追截与协力日志仍用于本案联动调查。（依据：实机诊断缺口与流程2026-10-18）

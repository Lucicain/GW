# 灰袍使者：宣战前先谈

> 当前状态：使者机制已部署待实测；协办人的使者照常办完、台账显示使者进度与最近回报已部署待实测；比武装备词条见 lord-combat.md
> 最后验收：未建立检查点
> 已复核至：`1782a40`（2026-10-16）
> 覆盖源码：`PoliceEnforcementBehavior.Envoy.cs`
> 待实测：目标在城里时使者进城谈；结局更多样（打折、宽限、单挑、投案）；正在打仗的目标投案时使者等他打完再带走；协办人的使者照常谈完；台账能看到使者进度和最近回报；agent 核对 `ENVOY_*` 日志

灰袍领主对原版罪犯也走谈判，不只玩家能谈。（依据：用户裁定 2026-10-15）
案件生命周期见 [案件](case-enforcement.md)；谈判规则本身见 [野外执法](field-arrest.md)；使者的出队与归队和追截队共用，见 [追截队](case-interceptors.md)。

## 什么时候派

承办领主每小时走到宣战判定之前（`UpdateTasks` → `HoldWarForEnvoy`），这宗案子还没派过使者就派一支：

- 目标不是玩家、有领主带队；灰袍与他的势力还没开战；不是玩家正承办的目标。他在烧村、在别人军团里都照派照谈。
  （依据：用户裁定 2026-10-15：正在犯罪也无所谓，震慑上了他多半会停）
- 使者从承办领主自己队里抽 `EnvoySize`（5）个没受伤的兵：骑兵优先、灰袍兵优先、兵阶高的优先，骑兵不够就由别的兵补上，
  不是只要骑兵。船照临时队的规矩向主队借，在海上也能派。（依据：用户裁定 2026-10-15）
- 承办领主正在打仗时这一小时先不宣战，仗打完就派。
- 领主在别人的军团里，或在海上只剩自己那条船（临时队出不了门，`IsStrandedAtSea`）时，这一小时派不出，照常走宣战判定。
  灰袍已经和他的势力开战，这宗案子不派使者。
  派不出的原因写 `ENVOY_NOT_SENT`（同一宗案子原因变了才再写）。
- 使者不主动打任何人：好斗度置零，原版进攻评分乘它，路边的劫匪勾不走它；逃跑判断不动，打不过的照样躲。
  被人打过一仗后原版会把它停在原地，使者每小时发现自己停着就要原版立刻重新决策，接着去找人。
  （依据：实机诊断 2026-10-15，使者全部的仗都是自己冲劫匪打起来的，打完原地停了约 11 小时；C#反编译 v1.4.8 `DefaultMobilePartyAIModel`）
- 承办领主被调去协力别人的案子时，自己的案子留在他手上、协力期间暂停，路上的使者照常去谈：谈成就结案，谈崩的等协力结束他接着办；
  协力中约成比武，他离开协力组去赴约。协力期间他在别人军团里，派不出新使者。（依据：用户裁定 2026-10-16）
  协力规则见 [案件](case-enforcement.md)「协力编队」。
- 使者用护送去跟目标：跟随中立部队不会触发遭遇，没宣战就打不起来。

使者在路上、双方约了比武时，这宗案子不宣战，也不调协办人。使者超过 `EnvoyTimeoutHours`（72）还没碰到人、被人吃掉、
或者灰袍与他的势力已经开战，算谈崩。

## 怎么谈

玩家接手普通悬赏或[赎罪](atonement.md)后，按统一委派归属阻止再派使者，路上的使者返程；已有普通承办任务也释放。已谈崩的历史保留，玩家放下后同案仍不再谈；已销案、只等战斗结束押人/扣兵的 `Aftermath` 继续完成交割。新给玩家选案时排除NPC已经约定宽限、收款或比武的案卷，避免转单打断承诺。（依据：源码复核与离线回归2026-10-15）

碰到目标时当场出结果，没有对话：走到原版军团成员会合的距离（海上用海上的距离）；他在城里、村里时，使者往那座定居点去，
进去或走到城下 3 格内（与火誓者到达判定同一个 `GwpFireswornBehavior.HasArrived`）就算碰到，进去谈。

- 第一层与玩家当面谈相同（`GwpNegotiationResistance`）。实力至上：抗性和肯不肯谈的判断用灰袍**主队**和目标的实力，
  不用使者自己的；两边都按实际一起行动的那一组算（已挂靠的军团、攻城营），他在别人军团里时背后就是那支军团。
  （依据：用户裁定 2026-10-15）来谈的人按承办领主算：名望取他家族的，口才取他本人的，分量按普通（不享受玩家的威望或戴罪档）。
- 掷法照原版说服：起手进度、每条要点若干次说辞、大失败结束整层（`SimulatePersuasion`，
  依据：C#反编译 v1.4.8 `DefaultPersuasionModel`；原版 AI 之间结婚也是不走对话、按概率结成同一个结局，
  依据：C#反编译 v1.4.8 `RomanceCampaignBehavior.CheckNpcMarriages`）。
- 拒谈或第一层没谈下来：谈崩。
- 第二层性格至上（用户裁定 2026-10-15）：他打算怎么了结只按性格抽（[野外执法](field-arrest.md)「他打算怎么了结」），
  抽到什么就照办，不再把他拉回照数全缴。第二层只在交钱的打算上讨价还价：谈下来，他肯给的比例往全额挪一半
  （讨价还价 70%→85%、骗一道 50%→75%、只认自己的事 40%→70%）；谈不下来按他说的数。抗性公式见野外执法「两层谈判」。

| 他的打算 | 结果 |
|---|---|
| 照数全缴 | 收全款 |
| 讨价还价、骗一道、只认自己的事 | 按讨价还价后的比例收；只认自己的事的照旧杀自己 5 个兵 |
| 塞私钱 | 钱进承办领主口袋，案子销掉、不记功，案底一点不少。不算谈崩（依据：用户裁定 2026-10-15） |
| 人跟你走 | 震慑、清账、按办成销案，使者把他带走，回主队时交给承办领主 |
| 请宽限 | 见下节 |
| 单挑 | 约比武，见下节 |

- 谈妥那一刻案子就结了。使者路上出事（钱被抢、押的人被救走）是灰袍的风险，不让他担。（依据：用户裁定 2026-10-15）
  收到的钱交给使者带回，归队时进公库；他名下的账按实缴清（`GwpFieldReportLedger.SettleWithWardens`，与玩家当面收钱同一套），
  并记一次灰袍执法；承办领主去忙别的事。
- 他正在打仗（多半就是在烧村、抢商队）也当场谈，案子当场结。只有要动他名册的两件（押他走、看他杀兵）等他这仗打完再办，
  使者跟着他等（`Aftermath`，进存档，72 小时没办成就作罢）；打仗时改名册会和原版战斗结算对不上。
- 谈崩之后这宗案子不再派使者，照原来的宣战流程走。谈崩记录留到销案为止。（依据：用户裁定 2026-10-15）
- 除了单挑，使者的各种结局都不给玩家提示。（依据：用户裁定 2026-10-15）

## 宽限

给 `GraceHours`（72）小时。承办领主当场放下这宗案子，直接去接下一个差事；宽限期里和收钱的使者在路上时，
谁都不接这宗案子（接案、就近改追同一道门 `CanPickUpCase`）。到期由离他最近的灰袍领主派一趟只收钱的使者，
不再谈：他的钱够就照数收、按办成销案，不够算谈崩，案子回台账照常追捕。（依据：用户裁定 2026-10-15）

收钱那趟不必他作主，他在别人军团里也照收。离他最近的领主这一小时派不了（正在打仗等）就换下一个近的，
都派不了就下一小时再试。宽限期里他的势力和灰袍打起来了，算谈崩。

## 单挑：比武大会

他要单挑，就约到原版比武大会，谁名次靠前谁赢。（依据：用户裁定 2026-10-15）

- 场地：离双方中点最近、双方都进得去（不与任一方交战、没被围、没在叛乱）的 3 座城里，有比武的取最近那座；
  都没有就在最近那座新开一场。（依据：用户裁定 2026-10-15）
- 约定时左下角提示一次（谁向谁约、在哪座城），玩家可以去看或下场。两人留城等赛：灰袍领主靠欲望层的去城意图，
  原版目标直接下令进城并停掉他自己的决策（原版把这一位存进存档）。他在别人军团里当成员时先离队赴约，
  和原版成婚时离开军团同一个做法（`MarriageAction`）。（依据：用户裁定 2026-10-15：留城等赛）
- 比武结束（原版自行结算或玩家在场）时两人都在城里才算数：夺冠的赢；玩家在场那场按打到第几轮比；
  原版自行结算只算出冠军，两人都没夺冠就按原版比武评分 ×(0.75+0.25×随机) 再比一次。（依据：用户裁定 2026-10-15）
- 原版新开的比武要满 10 天才可能自行结束（依据：C#反编译 v1.4.8 `DefaultTournamentModel.GetTournamentEndChance`），
  所以约定最多等 `TournamentDuelTimeoutDays`（5）天：到期两人都在城里，就用原版 `ResolveTournament` 把那场打完；
  有人没到就直接按评分比。那场比武在两人到之前被别人打完了，就再开一场。
- 结果再提示一次。灰袍领主赢：他照数全缴，钱直接入公库；他赢：按约免罚，案子销掉，案底照留。
- 一方战败、被俘或城被围：约定作废，两人放开，算谈崩。

## 比武强度与buff生效范围

灰袍领主与犯人的实际比武已按用户要求接入[身份战斗加成](lord-combat.md)，模拟评分保留原版。现行约斗比较整场大会名次，并未固定一对一赛程；分组、队友和其他参赛者都会影响结果。（依据：用户反馈、TournamentPlace/OnTournamentFinished源码复核 2026-10-15）

- **无人进场的整场结算、同名次再比较**：原版 `DefaultTournamentModel.GetTournamentSimulationScore` 为 `(英雄?1:0.4) × [max(单手,双手,长杆)+运动+骑术] ×0.01`，再乘0.75～1的随机系数。本模组WardenOutscores直接调用这个模型，没有额外灰袍胜率或场景buff折算；已读NavalDLCTournamentModel对此仅委托BaseModel。（依据：当前1.4.8 C#反编译、源码复核）
- **玩家入场但跳过的比赛**：原版TournamentFightMissionController.Simulate用CharacterObject.GetSimulationAttackPower与MatchEquipment计算，不创建实际踢击/击倒/Agent临时成长事件。它涉及原配护甲、比赛装备与静态技能，但不等于上述整场分数公式。（依据：当前安装SandBox.dll与CampaignSystem.dll C#反编译）
- **实际演出的比赛**：PrepareForMatch按城镇文化/队伍人数模板发MatchEquipment，再复制参赛者护甲5～9号槽（DefaultTournamentModel.GetParticipantArmor）；Spawn显式传MatchEquipment。灰袍原配剑/骑枪/大盾与战马通常被比赛模板替代；灰袍领主通过身份继承对应场景词条。护甲不能一概说被剥掉。（依据：当前安装1.4.8 TournamentFightMissionController/GetParticipantArmor反编译）
- 身份类踢/盾击、命中后临时技能仍注册在比赛场景，没有仅限野战的注册条件；领主80%踢/盾击击倒有身体命中、敌对、人类步行目标等条件，不是挥剑80%击倒。其数值与触发只在[双刀与通用战斗](dual-blade.md)定义。物品/坐骑词条只在[兵种与武器](troop-combat.md)定义。
- 六位领主开局采用原版专精配置，尤其文职成员并非高步战技能；当前初始表及清perk写入点归[家族](family.md)。军械库方案覆盖非英雄士兵，英雄不从中获得额外套装/自动结算加成，见[军械库](firesworn-armory.md)。

实战比武的触发条件如下，具体数值仅在所属战斗state维护；领主身份例外的范围只在[lord-combat.md](lord-combat.md)定义。（依据：用户裁定、源码复核2026-10-16）

| 加强 | 实战比武条件 | 数值归属 |
|---|---|---|
| 踢/盾击控制、动作硬直、盾对盾破防、踢空补控 | 灰袍身份及各自命中/距离/目标条件，普通比赛武器仍可 | [通用战斗](dual-blade.md) |
| 临时单手/运动成长、弓术成长 | 灰袍命中踢/盾击；灰袍使用任何Bow技能武器射箭 | [通用战斗](dual-blade.md) |
| 灰袍穿刺箭的击倒与盾伤 | 灰袍领主使用普通远程/弹药也可；其他射手仍须gwarrows | [武器词条](troop-combat.md) |
| 专属近战武器的击倒/打下马/武器招架破防 | 灰袍领主普通近战也可；武器招架破防不等于普通挥剑破盾 | [武器词条](troop-combat.md) |
| 双刀出招保护与挥砍延续 | 实际装配/持用双刀及对应动作，不自动给领主 | [双刀](dual-blade.md) |
| 大盾耐久与被动覆盖、踢/盾击时身体近战保护 | 灰袍领主普通盾也可；动作保护仍须持盾且正踢/盾击 | [武器](troop-combat.md)、[通用战斗](dual-blade.md) |
| 专属战马冲撞/小伤害反应/人立/分担骑手伤害 | 灰袍领主当前坐骑也可；其他骑手仍须gw_warhorse | [战马](troop-combat.md) |

以上触发型效果在纯模拟/跳过中不执行；死战不退仅Battle模式，竞技大会Tournament模式不适用，见[死战](warden-resolve.md)。实际战斗的装备词条身份扩展不改变模拟评分。（依据：用户裁定2026-10-16）

截至本轮读取的当前案件日志仅见梵蒂对lord_B8_s的一次 `envoy_duel_won_1000`；弥瑟对lord_NE9_l有约战记录但无已记录结算。现有日志不含双方实时技能、最终模型类型、比赛武器与单击buff命中，不能声称已测出总体胜率或证实具体一次战斗的全部效果。（依据：本机在役日志2026-10-15）

## 存档

使者案按案卷记在 `_envoyCases`（`gwp_enf_envoy_*`）：阶段、承办人、使者、目标、比武城、截止时刻、等着办的那件事。比武结果若在
任务场景里得出，先记下、下一个小时结算。使者小队本身按追截队的存法存（`DelayPatrolState.IsEnvoy`）。

## 回退

使者机制之前为 `90a3f4b`：`git revert` 本次存档即可去掉使者；谈判抗性公式抽到 `GwpNegotiationPolicy` 的部分对玩家行为不变。（依据：流程）

## 台账上的使者

灰袍事务界面（`GwpCaseArchiveScreen`）里，开着的案子在承办那一栏后面接「使者：…」：在路上（最多还要几小时）、宽限到期去收钱、
给了宽限到哪天、约在哪座城比武、谈崩照常追捕；承办人正在协助别人时另写「暂停：正在协助某某」。
最近 `EnvoyReportsKept`（12）次谈判结果单独成行（谁派的、对谁、结果和金额），放在案件列表最后；案子结了也看得到。
回报在出结果那一刻记下，进存档（`gwp_enf_envoy_report_*`）。（依据：用户裁定 2026-10-16：显示使者进度和结果）

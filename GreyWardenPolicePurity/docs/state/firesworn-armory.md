## 领装顺序与范围

继续按完整编制择优预留九类，不采用少量备装备额。差装、没人能用的和超额退持有者背包，村庄对应待售货仓；不删除实际库存。（依据：用户裁定2026-10-20）

| 类别 | 范围 |
|---|---|
| 头 / 身 / 腿 / 手 | 四类分别计编制 |
| 主武器 | 单手、双手、长杆共用一类 |
| 盾 | 盾牌 |
| 投掷 | 投矛、飞斧、飞刀等 |
| 远程 | 弓、弩共用一类 |
| 弹药 | 箭、弩矢共用一类，实际发放匹配兵器 |

上表共九类，各类已配加预留不超过编制口径，编制200且库存充足可留最多1800件；不是每种武器小类分别留200件。装备保留实际品质，强度优先于售价。高阶只补空位、低阶择强换装的规则保持，骑乘限制与弹药配对见下文。（依据：现行分类、用户裁定2026-10-20）

ARMED只表示原配或库装有主武器/远程，不代表护甲或装备质量；村间调剂已独立按人均装备质量计算，规则只在[转运](firesworn-parties.md#军械质量调剂)维护。（依据：源码2026-10-20）

- 玩家主队、每位灰袍领主人物、每个信众村和在役火誓者无领主队各一本军械账；物品按ID、品质和数量保存。普通兵原配不计入库账，实际分给士兵的库装仍计在库账中，不能再把配装数量加一次当库存。（依据：设计）
- 所有非英雄灰袍兵参与分配，身份复用公共 `IsGuardTroop`；已登记的原版信众村民队另包含其实际普通村民，普通村民可择强换装，其他队伍非灰袍兵仍排除。村民队的生成和精锐交换只在[村民队](firesworn-villagers.md)定义。（依据：用户裁定2026-10-16）兵种按Tier降序，同阶按StringId固定排序；每个兵依次从按实际强度降序排列的库存里挑，满足本兵种技能门槛后才发，不生成缺货物品。（依据：用户裁定 2026-10-15「最顶级的人先挑、一级一级往下」；同阶固定顺序设计）
- 灰袍轻步兵 `gwrecruit` 及以上、其他灰袍兵只补原配空位，空位里拿库里最好的；已占护甲格和武器一律不替换、不重排，因为高阶原配很多带灰袍词条和加成。原配披风/印章、坐骑/马具保留。原配有同类主武器、投掷、盾或远程时不额外塞第二件；空位够时可以补上原配没有的类别（例如弓箭、投掷）；双刀和弓箭所占四格原样保留。（依据：用户裁定 2026-10-15、2026-10-16「高级士兵的装备不能被替换，只能补空位」；具体分类设计）
- 狂信者 `gwzealot`、灰袍新兵 `gwnewrecruit` 可以拿比本套原配更强的装备替换。肩部印章写在兵种原配里（见[装备](warden-gear.md)「兵种原配」），军械库不发肩部，也不发马。（依据：用户裁定 2026-10-05/10-08/10-15/10-16）
- 配装选每名兵种内序号对应的**一套完整原配**，多套预设按序号轮换，按实际这一套判断空格；不再把所有预设的最强项目合并为OwnBest。实战使用同一份完整配装，不在Spawn阶段另抽一套；原配仍照原版逐件抽品质，库装保留库存中的品质。名册与库存相同则方案可重算，同版存读后接续。（依据：设计；原版1.4.8 Equipment.GetRandomEquipmentElements、Mission.SpawnAgent及项目整套预设补丁源码复核）
- 明确传入 `AgentOverridenSpawnEquipment` 的场景装备由原调用方负责，军械补丁不拿另一套原配的计划覆盖它。普通战役生成使用军械分配。（依据：C#反编译1.4.8 Mission.SpawnAgent；设计）

## 格子、技能与强度

- 头、身、腿、手四类护甲分别选；库装不配披风、马、马具，男女有一方不能用的物品不发。高阶保留其兵种原配的马匹/马具，不是从库里新发。（依据：用户裁定 2026-10-08/10-15）
- 武器依次考虑主武器、投掷、远程与匹配弹药，最后是盾。只有Weapon0～3四格，旗帜格不参与。盾要求已有单手武器；每件领出前验证实际可用槽位，放不下就不扣库存。（依据：用户裁定 2026-10-08；C#反编译EquipmentIndex及实现设计）
- 弓配箭、弩配矢；要同时有弹药和位置才领远程。原配已有匹配弹药可只领弓弩，已有弓弩而缺弹药可只补弹药；高阶不替换不匹配的原配弹药。只有一个空位而缺一整组弓箭时不领，不能挤入第五格。（依据：设计）
- `CanUse` 按物品RelevantSkill/Difficulty与当前兵种技能判断。强度沿用原版ItemObject.Effectiveness公式并折入品质前缀修改的数值；低阶仅更强才换。高阶先判断空位，原配再差也不换。（依据：用户裁定 2026-10-08/10-15；C#反编译1.4.8）
- 套装里有马的（骑士）只领骑在马上用得了的武器：至少有一种用法没标 `requires_no_mount`，且不是 `CantReloadOnHorseback` 的弩。长弓、长枪等宁可留给步兵，不给骑兵白占格子。（依据：用户反馈 2026-10-16；C#反编译 v1.4.8 MBItem.GetItemUsageSetFlags、Native item_usage_sets.xml）
- 库存分类先检查现有所有灰袍兵与新兵/狂信者是否有人能用；高阶能用、低阶技能不足的装备不能提前当废品卖掉。没人能用的物品及禁止类别列入Surplus。（依据：本轮全兵种配装设计）

## 编制预留、流转与缓存

- 领主按max(编制上限,实际人数)、村庄按max(守村上限,在村守村人数)择优预留，各类已配库装算在额度内，未领库装的兵位及空位也留一件；库存不足不生成装备。无领主队只带实际套装，不留增长编制。（依据：用户裁定 2026-10-15；设计）
- 每天一次，留够全部编制的最好装备以后，多出来的进持有者的背包交给原版处理：领主部队进部队背包，照原版进城卖；村庄进货仓，由卖货队卖或运械队运走。交战中的持有者、被俘玩家和无领主队不做此日结退余量；不能把已配/预留物品当多余。（依据：用户裁定 2026-10-16，取代 10-15 的「领主余量留库」）
- 祭司招募、守村队直招共用 `MoveBestSets`，在村内记录扣人前按实际兵种带走该兵种分配中的前几套库装，扣源库、加目标库；各阶都适用。兵种原配不作为库装搬运。（依据：用户裁定招兵连装备带走；实现设计）
- 无领主队出发用实际队伍名册重新按阶分配：合并本队已有与源库库存，只补当前选中套装里缺的同品质物品。重复调用不重复领装。自主练兵送老兵已退休，旧在途实体的真实库存继续随队保存。（依据：用户裁定、生产方法回归）
- 无领主队军械账只留当前实际配装，不留增长编制；非战斗时未配出的Free/Surplus实际转入背包，背包货物走原版容量和缴获。转运和传教仍到目的村整队交人交装并入，不返村；旧练兵队整队落村也走公共归库。被打掉的人货不补发。（依据：用户裁定2026-10-20；实现设计）
- 平时配装由库存和各兵种人数重算，不存档；战斗内逐人借用快照另行保存，见下节；库存对象/VersionNo、每种人数与预留编制任一变化使缓存失效。升级但总人数不变也会重算。读档清缓存，每小时复核；战斗外每次取方案都按库存与名册复核（没变就命中缓存），原版升级、招兵不必等整点；持有者在战斗中时已有方案冻结，不因伤亡重发库装。（依据：C#反编译ItemRoster.VersionNo；设计）

## 自动结算、战损与销队

- 自动结算按**该兵种实际额外领出的库装**算加成，原配不重复加。武器取主武器/投掷/远程中最高阶的逐兵平均值，每阶加6%伤害；四个护甲格的额外库装平均阶数a，使所受伤害乘1/(1+0.08a)。原配已有弓、只补箭时不额外算一把弓的伤害阶数。各兵种的两个阶数在建方案时算好，模拟命中只查表。（依据：用户裁定军械影响自动结算；本轮全兵种方案设计）
- MapEventParty完整逐人名册按UniqueSeed排序固定分配；实战AgentOrigin.UniqueSeed直接领取对应套，自动结算沿同一名册分配。同一MapEvent跨场景沿用；原版Update清空名册并重建编号前记录阵亡/负伤/溃逃，之后按兵种和伤情接续存活者的实际配装，旧轮次阵亡/溃逃配装保留到整场结算，不能被再次发给新兵。（依据：用户裁定；原版1.4.8 MapEventParty.Update/MapEventSide.MakeReadyParty反编译及生产回归2026-10-20）
- 战斗借用快照通过10个GWPP_FsBattle前缀的List<string>/List<int>键保存部队ID、持有人、兵种、编号、状态、原配及借用品质/槽位，不注册新保存类型、不重复生成物品；OnSessionLaunched接回实际MapEventParty。旧档没有新键时保留原库存，由当前原版名册建立分装；不能恢复旧版本从未记录的前轮逐人配装。原版战后先RemovePartyLeader再发MapEventEnded，军械归属在开战/排兵时记录，避免领主被俘后无法扣实际配装。（依据：用户同版接续要求；原版MapEvent战果提交顺序、生产保存/重排/分俘边界回归2026-10-20）
- 死亡时只记原版人员状态，不立即扣装备；只有整体战败才结算留在战场的库装，包括阵亡、负伤及全败被俘者；溃逃离场者保留，撤退时仍能离开的活兵保留。胜方回收自己的库装。逐件33%给胜方（玩家参战进玩家背包，否则胜方领头部队），其余损毁；只扣这一人的额外库装，不扣原配或库内未发放库存。（依据：用户裁定2026-10-20；撤退/被俘分流设计）
- 领主军械归人物ID，沿既有GWPP_FsArmory结构保存hero:<Hero.StringId>键；旧部队ID库在读档/首次使用/整点复核时实际并入对应人物库并删除旧键，不复制。领主部队覆灭或被俘不把余库送村；无部队时库存休眠，不按0人数清退，重新领队直接用同一个人物库。永久死亡人物的库暂保留，继承处置未定，本轮不擅自转村或删除。玩家仍用原主队库，战败/被俘保留未发放库存，被俘时不日结清退。（依据：用户裁定2026-10-20；归属及旧档迁移设计）
- 无领主队销毁时，在已结算配装之外的剩余军械也逐件33%交消灭者，其余损毁，不再100%赠予；没有消灭者时只清已销毁队的残账。运输货物在真实背包，原版自行分配，不纳入库装33%抽签。抵达交付后销队前已转走的库存不再扣第二次。（依据：用户裁定2026-10-20，末次裁定运输回原版背包）

## 战场缴获与入库分流

- 军械库只收灰袍兵能用的兵器护甲：配装类别之内（头、身、腿、手、主武器、盾、投掷、弓弩、箭矢），男女都能用，且至少一种灰袍兵种的技能够得着。马、马具、披风和谁都用不了的不进库，进持有者自己的背包——领主部队、无领主队进部队背包，照原版去卖；村子进货仓。所有入库（尸体缴获、纯化交装、进村捐赠、无领主队卸货、领主余量捐村）都经 `Store` / `IsArmoryItem` 这一处判断。（依据：用户裁定 2026-10-16）
- 军械主要来自尸体缴获、纯化兵种交装和实际捐赠/物流；不扒俘虏。原版兵换灰袍兵时交出第一套原配，按上一条分流。（依据：用户裁定 2026-10-06/10-15/10-16）
- 村内焚烧普通俘虏只通过BurnPairs产出灰袍兵，再由JoinGuard加入名册；新兵自带兵种原配，但该链不调用DepositTroopKits，不额外向军械账生成物品。原部队普通兵纯化是另一条入口，由GwpWardenPurification调用DepositTroopKits交出原装备。（依据：烧俘虏装备疑问；生产调用链复核2026-10-20）
- 灰袍领主部队与信众村民兵走原版玩家尸体缴获入口，按贡献份额分尸体，每次GetLootedItemFromTroop从一套装备按价值/概率抽取，可能空手，同类一次一件。普通背包、钱和俘虏仍走原版分配；民兵守赢可获军械。（依据：C#反编译1.4.8 MapEvent/DefaultBattleRewardModel）
- 分流之前留在领主军械库里的马之类，领主进信众村捐余量时一并交出：能用的进村军械库，其余进村货仓；村子的则由日结转货仓。现存资源沿实际流转处理。（依据：当前实现；用户存档裁定2026-10-19）
- 领主背包多出的东西（用不了的缴获和每天移出的多余装备）照原版进城卖。从前领主卡城不走，是军械余量倒进背包、越堆越多（实机诊断 2026-10-15）；现在全编制预留，进背包的只是更差或用不了的东西。`DAILY_LORD` 的 `inventoryValue` 与 `ARMORY_SURPLUS_TO_BACKPACK` 用来观察背包有没有持续上涨。（依据：用户裁定 2026-10-16）

## 玩家军械库

- 事务第四页显示主队实际军械与编制，“整理军械”打开原版Stash双栏库存，左侧军械、右侧玩家背包，可存入及取回。操作要求已入会、灰袍声望达到20、主队活跃且不在战斗；家族百科彩蛋只放行浏览。（依据：用户裁定2026-10-20；沿用事务准入设计）
- 账本按主队StringId，复用GWPP_FsArmory的物品ID/品质/数量保存，无新键或类型；旧档无主队条目按空库开始，不动村/其他队库存。已分给士兵的库装仍在账内，不额外复制装备。（依据：用户存档裁定；生产保存回归2026-10-20）
- 确认后共用BuildPlanFor/BuildPlan，按max(部队编制,实际人数)逐类择优保留，多余或不适用品退回背包；按强度而非价格挑。高阶只补空位，新兵/狂信者择强换装，规则同上文。日结沿用余量退背包，战斗中不整理，实战与自动结算用同一本账。（依据：用户要求同灰袍规则；生产回归2026-10-20）
- 玩家战利品仍由原版交玩家挑选，不自动分流军械库，玩家自行从背包存取。原版取消恢复双方库存，取消后不执行本次择优退余量；重置后可重新操作并确认。关闭库存回到事务军械页并读取实际库存。（依据：用户要求自行调控；安装版Stash/CloseInventoryPresentation/ResetLogic及生产入口执行2026-10-20）
- 玩家军械库若要撤回：已有主队库存是真实物品，回退前先实际取回，不直接删账。（依据：流程2026-10-20）

## 开发版查看与验证

领主军械库只列实际军械账，不列领主背包；村庄货仓查看保留。（依据：用户裁定2026-10-19）

开发版在村庄菜单及灰袍领主对话里看各自库房：村庄显示军械与待售货仓，领主仅显示军械，不读取背包；对话入口中英文明确「军械库」。列物品、品质、件数和价值，只看不能拿，玩家版无入口；不要求玩家入会。摘要的MEN涵盖各阶，ARMED包括原配/库装主武器与远程，不把原配齐全的高阶兵误报为空手。（依据：用户裁定 2026-10-07/10-08/2026-10-19；统计实现）

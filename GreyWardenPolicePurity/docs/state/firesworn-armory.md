## 领装顺序与范围

额度按装备种类计，每种上限都是编制人数：防具每个部位一种；武器按物品类别加武器类别细分，单手剑、单手斧、钉锤、双手剑、单手/双手/低握长杆、弓、弩、投矛、飞斧、箭、弩矢等各算一种，盾按盾牌一种。每个兵每种最多领一件，同种第二格（如两份箭）保留原配。分发对所有持有者都按种类计；留库只有玩家主队按种类计，主队编制为 200 时每种已配与预留合计最多 200 件，同属主武器的单手、双手、长杆互不挤占。NPC 领主、村庄和无领主队留库仍按下表配装类别计，灰袍每类只领一件，不为他们多囤各种武器。超额退持有者背包，村庄对应待售货仓。装备保留品质，按数值强度分配。（依据：用户裁定 2026-10-20、用户裁定 2026-11-15「每一个兵收集一整套防具，武器每个类型都收集一个」）

下表是配装类别，用于入库认定、灰袍「每类至多领一件」、NPC 留库、自动结算和村间调剂，不是分发额度单位：

| 类别 | 范围 |
|---|---|
| 头 / 身 / 腿 / 手 | 四个部位 |
| 肩部 | 披风、披肩等 `Cape` 类，普通兵参与配发 |
| 主武器 | 单手、双手、长杆 |
| 盾 | 盾牌 |
| 投掷 | 投矛、飞斧、飞刀等 |
| 远程 | 弓、弩 |
| 弹药 | 箭、弩矢，实际发放匹配兵器 |

ARMED只表示原配或库装有主武器/远程，不代表护甲或装备质量；村间调剂已独立按人均装备质量计算，规则只在[转运](firesworn-parties.md#军械质量调剂)维护。（依据：源码2026-10-20）

- 玩家主队、每位灰袍领主人物、每个信众村和在役火誓者无领主队各一本军械账；物品按ID、品质和数量保存。普通兵原配不计入库账，实际分给士兵的库装仍计在库账中，不能再把配装数量加一次当库存。（依据：设计）
- 已有军械账的队伍按实际名册向所有非英雄士兵配发；信众村的守村队里原版民兵也领村库装，战败照战损逐件扣村账。灰袍兵先按原有阶级顺序领，普通兵随后按阶从高到低，同阶按兵种 ID。普通兵只替换原配已占槽位，只领同类型且强度同等或更好的装备。武器按物品类别和武器类别同时匹配，例如单手剑和单手斧分开，弓配箭和弩配矢各自匹配。不同的等强物品可替换。村民队生成及精锐交换见[村民队](firesworn-villagers.md)。（依据：用户裁定 2026-10-15、用户裁定 2026-11-15；同阶排序与武器细分类设计）
- 灰袍轻步兵 `gwrecruit` 及以上、其他灰袍兵只补原配空位，空位里拿库里最好的；已占护甲格和武器一律不替换、不重排，因为高阶原配很多带灰袍词条和加成。原配披风/印章、坐骑/马具保留。原配有同类主武器、投掷、盾或远程时不额外塞第二件；空位够时可以补上原配没有的类别（例如弓箭、投掷）；双刀和弓箭所占四格原样保留。狂信者 `gwzealot`、灰袍新兵 `gwnewrecruit` 可以拿比本套原配更强的装备替换。肩部印章写在兵种原配里（见[装备](warden-gear.md)「兵种原配」），军械库不发肩部，也不发马。（依据：用户裁定 2026-10-05/10-08/10-15/10-16「高级士兵的装备不能被替换，只能补空位」；具体分类设计）
- 配装按每个兵种内序号轮换完整预设。实际领库装的普通兵和参与配装的灰袍兵，实战沿用配装所用的整套原配，库装保留库存品质。未领装备的普通兵继续由原版生成。明确传入 `AgentOverridenSpawnEquipment` 的场景由调用方提供装备。（依据：用户裁定 2026-11-15；原版 Equipment.GetRandomEquipmentElements 与 Mission.SpawnAgent）

## 格子、技能与强度

- 灰袍仍只从头、身、腿、手四类领护甲，只领男女都可用的装备；普通兵按本兵种能穿的对应部位换装，肩部同样比强度。马与马具沿用原配。（依据：用户裁定 2026-10-08、2026-10-15、2026-11-15）
- 武器依次考虑主武器、投掷、远程与匹配弹药，最后是盾。只有Weapon0～3四格，旗帜格不参与。盾要求已有单手武器；每件领出前验证实际可用槽位，放不下就不扣库存。弓配箭、弩配矢；要同时有弹药和位置才领远程。原配已有匹配弹药可只领弓弩，已有弓弩而缺弹药可只补弹药；高阶不替换不匹配的原配弹药。只有一个空位而缺一整组弓箭时不领，不能挤入第五格。（依据：用户裁定 2026-10-08；C#反编译EquipmentIndex及实现设计）
- `CanUse` 按物品 RelevantSkill/Difficulty 与当前兵种技能判断。强度沿用原版 ItemObject.Effectiveness 并折入品质前缀。NPC 库给满足技能、性别限制的现役兵和潜在灰袍低阶兵预留装备，玩家主队未配发的装备按类别和强度预留。（依据：用户裁定 2026-10-08、2026-10-15、2026-11-15；C# 反编译与分配设计）
- 套装里有马的（骑士）只领骑在马上用得了的武器：至少有一种用法没标 `requires_no_mount`，且不是 `CantReloadOnHorseback` 的弩。长弓、长枪等宁可留给步兵，不给骑兵白占格子。（依据：用户反馈 2026-10-16；C#反编译 v1.4.8 MBItem.GetItemUsageSetFlags、Native item_usage_sets.xml）

## 编制预留、流转与缓存

- 玩家主队每种库装上限取原版当前带兵上限。已配发也占额度，超出部分在确认整理或日结时退回背包。战斗中接续已借出的装备，新分配使用该种剩余额度。其他领主用 max(编制上限,实际人数)，村庄用 max(守村上限,在村灰袍人数) 预留，无领主队只带实际配装。（依据：用户裁定 2026-10-15、用户裁定 2026-11-15）
- 每天一次，留够全部编制的最好装备以后，多出来的进持有者的背包交给原版处理：领主部队进部队背包，照原版进城卖；村庄进货仓，由卖货队卖或运械队运走。交战中的持有者、被俘玩家和无领主队不做此日结退余量；不能把已配/预留物品当多余。（依据：用户裁定 2026-10-16，取代 10-15 的「领主余量留库」）
- 祭司招募、守村队直招共用 `MoveBestSets`，在村内记录扣人前按实际兵种带走该兵种分配中的前几套库装，扣源库、加目标库；各阶都适用。兵种原配不作为库装搬运。无领主队出发用实际队伍名册重新按阶分配：合并本队已有与源库库存，只补当前选中套装里缺的同品质物品，重复调用不重复领装。自主练兵送老兵已退休，旧在途实体的真实库存继续随队保存。（依据：用户裁定招兵连装备带走；实现设计与生产方法回归）
- 无领主队军械账只留当前实际配装，不留增长编制；非战斗时未配出的Free/Surplus实际转入背包，背包货物走原版容量和缴获。转运和传教仍到目的村整队交人交装并入，不返村；旧练兵队整队落村也走公共归库。被打掉的人货不补发。（依据：用户裁定2026-10-20；实现设计）
- 平时配装由库存和各兵种人数重算，不存档；战斗内逐人借用快照另行保存，见下节；库存对象/VersionNo、每种人数与预留编制任一变化使缓存失效。升级但总人数不变也会重算。读档清缓存，每小时复核；战斗外每次取方案都按库存与名册复核（没变就命中缓存），原版升级、招兵不必等整点；持有者在战斗中时已有方案冻结，不因伤亡重发库装。（依据：C#反编译ItemRoster.VersionNo；设计）

## 自动结算、战损与销队

- 自动结算用实际领出的库装。武器取主武器、投掷、远程中最高阶的逐兵平均值，每阶加 6% 伤害。灰袍按四个护甲格，普通兵加肩部共五格，平均阶数 a 使所受伤害乘 1/(1+0.08a)。只领弹药的情况不计武器加成。（依据：用户裁定军械影响自动结算；2026-11-15 普通兵配装设计）
- MapEventParty完整逐人名册按UniqueSeed排序固定分配；实战AgentOrigin.UniqueSeed直接领取对应套，自动结算沿同一名册分配。同一MapEvent跨场景沿用；原版Update清空名册并重建编号前记录阵亡/负伤/溃逃，之后按兵种和伤情接续存活者的实际配装，旧轮次阵亡/溃逃配装保留到整场结算，不能被再次发给新兵。战斗借用快照通过10个GWPP_FsBattle前缀的List<string>/List<int>键保存部队ID、持有人、兵种、编号、状态、原配及借用品质/槽位，不注册新保存类型、不重复生成物品；OnSessionLaunched接回实际MapEventParty。旧档没有新键时保留原库存，由当前原版名册建立分装；不能恢复旧版本从未记录的前轮逐人配装。原版战后先RemovePartyLeader再发MapEventEnded，军械归属在开战/排兵时记录，避免领主被俘后无法扣实际配装。（依据：用户裁定与同版接续要求；原版1.4.8 MapEventParty.Update/MapEventSide.MakeReadyParty反编译、MapEvent战果提交顺序及生产保存/重排/分俘边界回归2026-10-20）
- 死亡时只记原版人员状态，不立即扣装备；只有整体战败才结算留在战场的库装，包括阵亡、负伤及全败被俘者；溃逃离场者保留，撤退时仍能离开的活兵保留。胜方回收自己的库装。逐件33%给胜方（玩家参战进玩家背包，否则胜方领头部队），其余损毁；只扣这一人的额外库装，不扣原配或库内未发放库存。无领主队销毁时，在已结算配装之外的剩余军械也逐件33%交消灭者，其余损毁，不再100%赠予；没有消灭者时只清已销毁队的残账。运输货物在真实背包，原版自行分配，不纳入库装33%抽签。抵达交付后销队前已转走的库存不再扣第二次。（依据：用户裁定2026-10-20，末次裁定运输回原版背包；撤退/被俘分流设计）
- 领主军械归人物ID，沿既有GWPP_FsArmory结构保存hero:<Hero.StringId>键；旧部队ID库在读档/首次使用/整点复核时实际并入对应人物库并删除旧键，不复制。领主部队覆灭或被俘不把余库送村；无部队时库存休眠，不按0人数清退，重新领队直接用同一个人物库。永久死亡人物的库暂保留，继承处置未定，本轮不擅自转村或删除。玩家仍用原主队库，战败/被俘保留未发放库存，被俘时不日结清退。（依据：用户裁定2026-10-20；归属及旧档迁移设计）
- 已知缺陷：2026-11-06 21:35 读档约 9 秒后的首场自动结算里，`RebindBattleLoadout` 从库存账扣除已借出配装时，原版 `ItemRoster.AddToCounts` 报「Trying to delete an element from Item Roster that does not exist!」：至少一件借出物品已不在该持有者账上。原版只断言不扣、不崩溃；后果是该物品的可用数不再被扣减，可能被同场另一人重复借出。历史仅此一次，根因未明（读档接回的借用快照与账本品质不一致，或账本在战斗中途被别处扣减，都只是猜测），未改业务；已加 `ARMORY_BATTLE_KIT_MISSING` 记持有者、物品、品质与同物品账面数。（依据：实机故障日志 2026-11-06）

## 战场缴获与入库分流

- 入库按配装类别认定，包括肩部。马和马具等其他类别进部队背包或待售货仓。`Store` / `IsArmoryItem` 统一军械分类，适用于尸体缴获、纯化交装、进村捐赠、无领主队卸货和玩家交付。纯化仍交出普通兵第一套原配。领装再查兵种实际限制。（依据：用户裁定 2026-10-06、2026-10-15、2026-10-16、用户裁定 2026-11-15）
- 村内焚烧普通俘虏只通过BurnPairs产出灰袍兵，再由JoinGuard加入名册；新兵自带兵种原配，但该链不调用DepositTroopKits，不额外向军械账生成物品。原部队普通兵纯化是另一条入口，由GwpWardenPurification调用DepositTroopKits交出原装备。（依据：烧俘虏装备疑问；生产调用链复核2026-10-20）
- 灰袍领主部队与信众村民兵走原版玩家尸体缴获入口，按贡献份额分尸体，每次GetLootedItemFromTroop从一套装备按价值/概率抽取，可能空手，同类一次一件。普通背包、钱和俘虏仍走原版分配；民兵守赢可获军械。（依据：C#反编译1.4.8 MapEvent/DefaultBattleRewardModel）
- 分流之前留在领主军械库里的马之类，领主进信众村捐余量时一并交出：能用的进村军械库，其余进村货仓；村子的则由日结转货仓。领主背包多出的东西（用不了的缴获和每天移出的多余装备）照原版进城卖。从前领主卡城不走，是军械余量倒进背包、越堆越多（实机诊断 2026-10-15）；现在全编制预留，进背包的只是更差或用不了的东西。`DAILY_LORD` 的 `inventoryValue` 与 `ARMORY_SURPLUS_TO_BACKPACK` 用来观察背包有没有持续上涨。（依据：用户裁定 2026-10-16、存档裁定2026-10-19）

## 玩家军械库

- 事务第四页显示主队实际军械与编制，“整理军械”打开原版Stash双栏库存，左侧军械、右侧玩家背包，可存入及取回。操作要求已入会、灰袍声望达到20、主队活跃且不在战斗；家族百科彩蛋只放行浏览。（依据：用户裁定2026-10-20；沿用事务准入设计）
- 账本按主队StringId，复用GWPP_FsArmory的物品ID/品质/数量保存，无新键或类型；旧档无主队条目按空库开始，不动村/其他队库存。已分给士兵的库装仍在账内，不额外复制装备。若要撤回玩家军械库：已有主队库存是真实物品，回退前先实际取回，不直接删账。（依据：用户存档裁定；生产保存回归与流程2026-10-20）
- 玩家按[带兵上限](#编制预留流转与缓存)整理军械。玩家自行从背包存取战利品。完成整理回到事务军械页并读取实际库存，取消和重置见[原版储藏界面](../vanilla/inventory-stash.md)。（依据：用户裁定 2026-10-20、用户裁定 2026-11-15）
- [向祭司交付军械](firesworn-economy.md#玩家向祭司交付)读取同一本主队军械账，成交后两边配装随账重算。（依据：用户裁定 2026-11-15）

## 开发版查看与验证

领主军械库只列实际军械账，不列领主背包；村庄货仓查看保留。开发版在村庄菜单及灰袍领主对话里看各自库房：村庄显示军械与待售货仓，领主仅显示军械，不读取背包；对话入口中英文明确「军械库」。列物品、品质、件数和价值，只看不能拿，玩家版无入口；不要求玩家入会。摘要的MEN涵盖各阶，ARMED包括原配/库装主武器与远程，不把原配齐全的高阶兵误报为空手。（依据：用户裁定 2026-10-07/10-08/2026-10-19；统计实现）

`DAILY_LORD` 先取得军械账持有人，再用有效编号查库存和配装。暂无持有人的部队仍记部队数据，标 `armoryHolder=-`。2026-11-11 15:38:27 同开内战后，首个日结遇到[已撤去领主的部队](family.md#本职)，旧诊断把空编号传给库存字典并崩溃一次。开发版 DLL 对照确认新分支跳过这次查表；已发布玩家 DLL 的 `WriteDailySummary` 是空方法。修复后核对了关闭内战的两次完整日结和同开内战读档的 14 次日结，两局均保留领主，空键异常复发 0 次，无持有人分支经过 0 次。（依据：本机异常堆栈、AI日志、实际进程模组参数与新旧 DLL 指令对照）

原版、RBM 与本模组马具均显式 Type=HorseHarness，subtype=body_armor 不改变按 Type 读取的分类。肩部使用原版 Cape 类型，入库规则见上文。（依据：物品 XML 2026-10-19；v1.5.7 ItemObject 类型）

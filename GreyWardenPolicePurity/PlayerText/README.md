# 玩家词句维护

维护入口是 [strings.json](strings.json)。中文、英文和已整理的出现情境放在同一条文本键下；[index.md](index.md)是生成的查找表。

1. 搜索玩家看到的句子或文本键，在 `strings.json` 同时修改 `en` 与 `zh`。保留花括号里的姓名、地点、数量等变量。
2. 运行 `python tools/Generate-PlayerText.py`，生成C#常量、中文语言XML、模块英文属性和查找表。
3. 构建会运行 `--check`，检查生成产物与入口一致、中英变量匹配，并拒绝重新把带文本键的完整句子写回行为代码。

行为代码引用 `GwpTextCatalog.gwp_…`；仍使用原版TextObject翻译、格式化和显示，没有另加文本加载器。动态谈判句子的英文片段也在此文件，`English_…`常量供原有拼键逻辑使用。

`en: null`表示这条旧中文未找到现行英文源，不凭空补译或删掉。`fragments`保留原有动态谈判默认英文，沿用原本调用行为。

新建文字时先加文本键与中英内容，再在行为代码引用对应常量，运行生成器。生成的 `GwpTextCatalog.g.cs`、中文语言XML与索引不作为手工维护入口。

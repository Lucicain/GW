收尾这一轮的开发记录。**照模板填，不要自由发挥写大段落。**

## 1. 先确定这轮碰了哪个子系统

看 `git status` 与 `git diff --stat`，对照 `GreyWardenPolicePurity/docs/state/README.md`
的映射表找到对应的 state 文件。

- 找不到对应文件（子系统在"尚未提取"清单里）→ **新建一个 state 文件**，
  按下面的固定开头写，并把它加进 `state/README.md` 的表格、从"尚未提取"里划掉。

## 2. 原地改写 state 文件

**改写，不是追加。** 结论被推翻就直接改掉那句话，不要写"但是后来又改成…"。
更新文件顶部：

```
> 当前状态：<已部署待实测 / 用户已实测确认 / 调查中未改代码 / 已明确不做>
> 最后验收：<commit hash 或"未建立检查点">
> 待实测：<一句话；没有就写"无">
```

只写**现在有效**的行为、阈值和实现方式。已撤回的候选单独列一张表，注明停放位置和
"不要恢复"。

## 3. 往 `docs/journal/<当月>.md` 末尾追加一条

```markdown
## <YYYY-MM-DD> <一句话标题>（<已部署待验 / 仅调查未改代码 / 已撤回>）

- **改了什么**：<一两句>
- **为什么**：<用户要求原文，或实测证据>
- **证据**：<日志行、反编译路径、实测读数；没有就写"仅构建期验证">
- **验证**：构建 <0 警告 0 错误>；<测试工程> <N> 项；预检 <类型/成员/加载/补丁绑定>；
  `Verify-LiveModule` <结果>
- **哈希**：隔离预检 / live 客户端 / live 编辑器 DLL SHA256 = `<hash>`
- **回退**：<备份目录绝对路径 + 旧 DLL hash + 源码回退步骤>
- **未做**：<有意跳过的，及原因>
- **state**：已更新 `state/<file>.md`
```

写进流水的是**这一轮发生了什么**；写进 state 的是**现在是什么样**。同一件事在两处
的写法不同，不要复制粘贴。

## 4. 报告给用户

一段话，包含：

- 改了哪几个文件（用 markdown 链接）
- 构建/测试/预检/镜像校验的实际结果——**失败就说失败并贴输出**，不要含糊
- 部署了没有、有没有开游戏、有没有发声、有没有建 ZIP
- 需要用户实机验证什么

## 边界

- **不更新** `_Module/README.md` / `README_EN.md`，除非用户明说要发新版本。
- **不创建**发布 ZIP。
- **不提交**，除非用户确认这轮功能实机可用（那时才是检查点）。
- 用户没说"实机确认可用"就不要写"已验收"。
